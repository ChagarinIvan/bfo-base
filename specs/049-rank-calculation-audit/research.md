# Исследование и итоговые решения

## Подтверждённые ошибки расчёта

1. Будущая ручная активация высших разрядов не назначала следующий ежедневный пересчёт.
2. Будущее подтверждение могло продлевать текущий период раньше своей даты.
3. Периоды строились по выполнению, хотя начало действия определяется активацией.
4. Сравнение с timestamp исключало часть последнего дня срока.

Обезличенные регрессии воспроизводят эти случаи. Связь с конкретным исходным понижением КМС до I не доказана. В простом примере действующий КМС и последующий I текущий высший разряд сохраняют.

## Карта входов

Импорт использует StandardEventPersonRankUpdater; ручной, ежедневный, массовый пересчёт, активация и перепривязка используют RebuildPersonRanksService. Оба пути вызывают один Domain PersonRanksUpdater. Перепривязка явно сохраняет старого владельца до очереди и пересчитывает его вместе с новым.

## Единая активация

RankActivationPolicy автоматически подтверждает I/КМС/МС/МСМК по допустимому равному/высшему выполнению с активацией не позже целевой даты, включая истёкшие основания. Низшее, более позднее, неподтверждённое, неактивное, недопустимое или чужое выполнение не подходит. Ручная дата приоритетна, месячное ожидание младших разрядов сохранено. Дополнительного флага в ProtocolLine и SQL-записи вычисленной даты нет.

## Простота аудита

По уточнениям пользователя аудит содержит trigger как enum, created как Impression и типизированные before/after. Остальные данные выводятся из состояний или не требуются. Нет operation/root IDs, отдельных статусов/причин/флагов, копий входных фактов и summary API. No-op не создаёт запись, что предотвращает ложные переходы при повторной обработке неизменных данных.

Domain PersonRanksUpdater рассчитывает и сохраняет изменение и аудит; Application управляет блокировкой/транзакцией и записью неуспешной попытки после rollback. Application-сервис не реализует Domain interface. Typed snapshot/entry не содержат array<string,mixed>; JSON принадлежит Infrastructure, массивы ответа принадлежат Application DTO/assembler.

Аудит сохранён независимо от производной истории. Чтение ограничено Slice perPage+1 и индексом person_id/id, без COUNT, eager-связей и запросов на каждую строку. Историческая коррекция использует тот же расчёт, preview без записи, apply явно и идемпотентно.

## Аудит создания ProtocolLine

Impression текущего импорта передаётся из ParseEventProtocolService через Event::parse в ProtocolLinesFactory::create. Он задаёт created и updated. Дальнейшие изменения сохраняют created. Для старых неизвестных значений общий ImpressionCast возвращает null. Проверены сохранение и каскад назначения спортсмена с фиксированными часами.

## Ограничения

До включения журнала достоверные причины неизвестны. Наблюдение о сборе стартов для вычисленного IIIю не объявлено исправлением этой фичи. Журнал сохраняет только состояние разрядов и идентификаторы, без ФИО или сырых протоколов.
