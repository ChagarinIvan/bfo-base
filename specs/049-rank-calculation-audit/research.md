# Исследование после ревью PR #175

## Существующие ошибки расчёта

Подтверждены регрессиями: будущая ручная активация не назначала пересчёт и могла преждевременно продлевать период; порядок активации отличался от порядка выполнения; сравнение timestamp исключало часть последнего дня. Эти исправления сохраняются. Связь с исходным конкретным понижением КМС до I не доказана.

## Владение и запись аудита

**Decision**: Person добавляет чистый RankAuditAction при updateRanks; PersonRepository сохраняет pending действия вместе с проекцией и историей. Повтор применения создаёт новую запись. Список очищается только после успешной записи.
**Rationale**: повторяет уже существующую передачу rankHistoryToPersist, делает источник аудита единственным, не требует снимков или новой фреймворк-связи Domain.
**Alternatives considered**: отдельный writer/updater для аудита, snapshot comparison, Eloquent audit model в Domain, hasMany на Infrastructure model, after-commit listener. Первые варианты усложняют модель/границы; listener нарушает атомарность.

## Форма результата

**Decision**: использовать существующий PersonRank и nextActivationOn в чистом action; при хранении пять полей образуют applied JSON, при чтении возвращается AppliedRankDto. Полных before/after и истории в журнале нет.
**Rationale**: это именно присваиваемые Person поля из общего комментария ревью. Причина и последовательность значений объясняют цепочку применений.
**Alternatives considered**: новый универсальный snapshot или list всех изменений истории. Они возвращают отвергнутую сложность. История выполнений остаётся существующей проекцией.

## Чтение

**Decision**: query person_rank_audit JOIN person active=true, select audit.*, order id DESC, стандартный Slice. Неизвестный/неактивный Person даёт пустую страницу без второго запроса.
**Rationale**: соответствует ревью, не загружает накопленный журнал при каждой загрузке Person. Автор приходит обычным ImpressionDto, без per-row lookup.
**Alternatives considered**: предварительный byId и PersonNotFound, eager всего журнала. Оба избыточны.

## Полный пересчёт

**Decision**: существующий persons:ranks:refill обходит всех активных по lazy ID и полностью заменяет производные поля и историю каждого в обычной транзакции rebuild. Причина Manual, переданная CLI явно. Daily использует Scheduled.
**Rationale**: repository уже полностью удаляет/перестраивает историю человека. Глобальная очистка до обработки опасна частично пустой базой при сбое и не нужна для полного результата.
**Alternatives considered**: CorrectPersonRanks preview/apply, отдельная глобальная truncate-команда, новый массовый сервис. Удаляются/не вводятся.

## ProtocolLine и миграция

**Decision**: добавить nullable timestamps/by, UPDATE JOIN distances/events перенести оба Impression, затем сделать все четыре поля NOT NULL. Создание новых строк использует Impression импорта; стандартный ImpressionCast остаётся без nullable веток.
**Rationale**: пользователь явно указал доступный источник ретроспективного заполнения. Это значения события, не восстановленное точное время изменения строки.
**Validation**: migration backfill проверяется на данных до применения миграции в изолированном интеграционном тесте; обычные мутации сохраняют created.

## Источники исследования

Прочитаны spec/review, конституция, архитектурный манифест и конкретные paths Person/updateRanks, EloquentPersonRepository/update, refill/daily commands, rank jobs, current audit API/UI. Два research-агента независимо проверили владение/запись и массовый rebuild, без правок файлов. Новых технологий и внешних зависимостей нет.

## Путь объединения событий, найденный финальным набором

Eloquent replicate по умолчанию исключает created_at/updated_at даже у ProtocolLine с WithoutTimestamps. Полный backend-набор выявил два сценария объединения, где новые обязательные поля не заполнялись. Копии получают created/updated из Impression создания объединённого Event перед save. Сохранность источников и разрядное поведение объединения остаются прежними; добавлена регрессия обоих Impression в UniteEventsTest.

## Проверка сохранения без повторного применения

Ожидающие действия аудита и payload производной истории очищаются методом Person::ranksPersisted после успешных записей. Иначе повторный repository save того же объекта мог удалить уже сохранённые строки истории и не вставить их заново, поскольку Eloquent считал их существующими. Интеграционный тест проверяет сохранность истории и ровно одну запись аудита после двух save.

Итоговая реализация и полный набор проверены; результаты находятся в plan.md. Бизнес-ошибок и копий истории в аудите нет, отдельная коррекция удалена, общая политика подтверждения сохранена.
