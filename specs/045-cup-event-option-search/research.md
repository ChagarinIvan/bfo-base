# Research: Поиск этапа для кубка

## Текущий дефект

`CreateCupEventPage.vue` запрашивает `perPage=100` и передаёт результат в PrimeVue Select с локальным фильтром. Подходящие этапы после первой сотни не доступны. `GET /api/v1/events` уже отдаёт `Slice` и заголовки страниц; `SearchEventDto` знает `year` и `notRelatedToCup`.

## Сортировка и поиск

**Decision**: Добавить в `SearchEventDto` только разрешённый `sortBy=date` и `sort=asc|desc`. `ListEvents` превращает их в сортировку `Criteria`; adapter дополняет дату идентификатором для устойчивого порядка. `competitionOrEventName` фильтрует `LOWER(events.name)` или `LOWER(competitions.name)` в одной сгруппированной SQL-условии перед пагинацией.

**Rationale**: Сортировка остаётся проверенной и не допускает произвольное имя SQL-колонки из запроса. Серверный поиск видит все подходящие строки, а не только текущую страницу.

**Alternative**: Загрузить все этапы и фильтровать в браузере. Это неограниченный ответ и не решает растущий список.

## UI

**Decision**: На странице создания использовать отдельное поле поиска с задержкой 300 мс, обычный Select без локального фильтра и `SlicePaginator` с 20 строками. Смена поиска сбрасывает страницу. При коротком вводе запрос не посылается; поздние ответы игнорируются. Выбор хранится отдельно от текущей страницы результатов.

**Rationale**: PrimeVue Select с локальным `filter` повторно отсеивает загруженную страницу и создаёт ложное впечатление поиска по всему набору. Отдельное поле явно показывает серверный поиск и позволяет листать результаты.

**Alternative**: Использовать `@filter` у Select. Он всё равно выполняет локальную фильтрацию вариантов и сложнее сохраняет выбранное значение между страницами.

## Граница области

Форма редактирования использует тот же компонент, но сохраняет прежнюю локальную логику. Новый режим включается только страницей создания. Действующий `getCupEventOptions` остаётся совместимым; для страницы создаётся функция с возвращаемыми заголовками страниц.

При проверке объединённых фильтров обнаружено, что старый `LEFT JOIN cup_events` возвращал уже связанный этап, если тот же этап был связан и с другим кубком. Условие исключения заменяется на `NOT EXISTS` для активной связи с текущим кубком; request-тест закрепляет этот случай.
