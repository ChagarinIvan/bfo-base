# Feature Specification: Поиск этапа при добавлении в кубок

**Feature Branch**: `master`

**Created**: 2026-10-11

**Status**: Implemented

**Input**: На странице `/app/cups/{cupId}/events/create` показывать подходящие этапы по дате от новых к старым, искать по названию соревнования или этапа среди всех подходящих записей и листать результаты по 20.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Найти и выбрать этап (Priority: P1)

Администратор добавляет этап в кубок. Он вводит часть названия соревнования или этапа и видит подходящие этапы, даже если их нет среди первых 20. Результаты отсортированы от новых дат к старым.

Поиск вводится в поле фильтра самого списка выбора этапа. Отдельного поля поиска на форме нет.

**Why this priority**: Сейчас форма загружает только первую часть списка и ищет внутри неё; подходящий этап может быть недоступен для выбора.

**Independent Test**: Создать больше 20 подходящих этапов, поместить искомый этап за пределами первой страницы и найти его по названию соревнования и по названию этапа.

**Acceptance Scenarios**:

1. **Given** больше 20 подходящих этапов, **When** администратор открывает форму, **Then** он видит первые 20 в порядке убывания даты и может перейти к следующим.
2. **Given** нужного этапа нет на первой странице, **When** администратор вводит часть названия соревнования, **Then** он видит этот этап среди результатов поиска.
3. **Given** нужного этапа нет на первой странице, **When** администратор вводит часть названия этапа, **Then** он видит этот этап среди результатов поиска.
4. **Given** администратор находится на второй странице, **When** он меняет поиск, **Then** результаты начинаются с первой страницы нового поиска.
5. **Given** подходящий этап найден, **When** администратор выбирает его и сохраняет форму, **Then** этап добавляется в кубок по действующим правилам.

### Edge Cases

- Пустой поиск возвращает обычный список подходящих этапов.
- Ввод от одного до двух символов не запускает поиск; форма объясняет минимальную длину.
- Поиск без совпадений показывает пустое состояние, а не этапы из предыдущего поиска.
- Более ранний медленный ответ не заменяет результаты нового запроса.
- Год кубка, исключение уже связанных с кубком этапов и существующие права доступа сохраняются.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Форма создания этапа кубка MUST показывать не более 20 подходящих этапов на странице и давать переход между страницами.
- **FR-002**: Подходящие этапы MUST выводиться по дате от новых к старым; этапы с одинаковой датой MUST иметь устойчивый порядок.
- **FR-003**: Поиск MUST находить этап, если часть введённого названия содержится в названии соревнования или самого этапа, независимо от текущей страницы.
- **FR-004**: Поиск MUST сохранять ограничения по году кубка и отсутствию активной связи с этим кубком.
- **FR-005**: Изменение или очистка поиска MUST возвращать первую страницу; короткий ввод и отсутствие совпадений MUST показывать понятное состояние.
- **FR-006**: Выбранный этап MUST оставаться выбранным при листании результатов, пока администратор не выберет другой.
- **FR-007**: Изменение MUST не менять правила создания этапа кубка и поведение формы редактирования.
- **FR-008**: Поиск MUST находиться внутри списка выбора этапа; результаты серверного поиска MUST отображаться без повторного локального отсеивания.

### Key Entities

- **Кубок**: Определяет год и уже связанные этапы.
- **Этап соревнования**: Кандидат для добавления в кубок с датой, названием и названием соревнования.
- **Результаты поиска**: Упорядоченная страница кандидатов и признак следующей страницы.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Каждый подходящий этап можно найти по трём и более символам названия соревнования или этапа, включая этапы за пределами первой страницы.
- **SC-002**: На каждой странице находится не более 20 этапов, а переход между страницами не меняет условия поиска.
- **SC-003**: После изменения поиска первая видимая страница соответствует новому запросу; устаревшие ответы не показываются.
- **SC-004**: Сохранение выбранного этапа работает тем же действием и по тем же правилам, что до изменения.

## Assumptions

- Исправление относится к форме создания; форма редактирования сохраняет нынешний выбор этапа.
- Поиск нечувствителен к регистру, принимает не менее трёх символов после удаления крайних пробелов.
- При одинаковой дате порядок определяется идентификатором этапа по возрастанию.
