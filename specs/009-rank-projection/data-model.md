# Модель данных: актуальный разряд и история разрядов

## Person

`Person` владеет материализованным актуальным состоянием и остаётся единственной
согласованной точкой изменения разрядов спортсмена.

| Поле | Значение | Правила |
|------|----------|---------|
| `current_rank` | Значение `Rank` | Обязателен; для отсутствия разряда — `Rank::WithoutRank` (`0`); в БД сохраняется integer backed value enum в `unsignedTinyInteger`. |
| `current_rank_started_on` | Начало текущего периода | Отсутствует для `б/р`. |
| `current_rank_activated_on` | Дата применения текущего разряда | Отсутствует, если выполнение ожидает ручной активации или разряда нет. |
| `current_rank_finished_on` | Последний день действия текущего разряда | Отсутствует для `б/р`; используется Scheduler для отбора кандидатов. |

### Индексы Person

| Индекс | Назначение |
|--------|------------|
| `(current_rank, active)` | Фильтр активных спортсменов с `rankId`. |
| `(current_rank_finished_on)` | Ежедневный отбор спортсменов, у которых закончился текущий период. |

Существующий `(club_id, active)` используется для сочетания `clubId + rankId`: сначала
отбирается небольшой клуб, затем проверяется разряд. Integration-тесты проверяют `EXPLAIN`
ключевых запросов, а не только наличие определения индекса в миграции. Новый широкий
составной индекс добавляется только если этот план перестанет быть достаточным на реальных
объёмах данных.

### Состояния

| Состояние | `current_rank` | Даты | Переход |
|-----------|----------------|------|---------|
| Нет разряда | `б/р` | все отсутствуют | Нет допустимой записи истории на дату расчёта. |
| Ожидает активации | `б/р` | все отсутствуют | Выполнение сохранено в истории, но не активировано. |
| Действующий | case `Rank` | начало и окончание обязательны; активация зависит от типа разряда | Калькулятор выбрал запись истории как действующую на дату расчёта. |
| Истёк | вычисляется заново | определяется следующей историей или `б/р` | Ежедневный Scheduler запускает rebuild. |

## PersonRankHistory

Производная запись истории; не aggregate root и не источник истины. Все записи принадлежат
одному `Person` и заменяются в рамках rebuild этого спортсмена.

| Поле | Значение | Правила |
|------|----------|---------|
| `id` | Идентификатор элемента истории | Технический ключ. |
| `person_id` | Владелец | Обязательная ссылка на `Person`. |
| `protocol_line_id` | Источник выполнения | Обязательная ссылка на идентифицированную строку протокола. |
| `distance_id` | Дистанция источника | Обязательная прямая ссылка для глубокого перехода и пакетного чтения. |
| `event_id` | Event источника | Обязательная прямая ссылка для глубокого перехода и пакетного чтения. |
| `competition_id` | Соревнование источника | Обязательная прямая ссылка для глубокого перехода и пакетного чтения. |
| `rank` | Выполненный/действующий `Rank` | Только enum cases, кроме `Rank::WithoutRank`; на границе хранится integer backed value case в `unsignedTinyInteger`. |
| `change_type` | Причина элемента | `RankChangeType`: `completion`, `extension`, `promotion` или `downgrade`; вычисляется правилами и отображается в истории. IIIю является обычным `completion`. |
| `achieved_on` | Дата старта-основания | Берётся из event источника. |
| `activated_on` | Дата применения | Может отсутствовать до ручной активации. |
| `started_on` | Начало периода | Вычисляется действующими правилами. |
| `finished_on` | Последний день периода | Вычисляется действующими правилами. |

Связи: `Person 1 — N PersonRankHistory`; каждая история связана с `ProtocolLine`,
`Distance`, `Event` и `Competition`. Идентификаторы источника намеренно дублируют путь
protocol line: это производная read model, которой нужны прямые deep links и пакетное
получение названий без вложенной цепочки relations. Названия не денормализуются, чтобы
переименование соревнования или event отображалось актуально.

`activated_on` всегда выводится из `ProtocolLine.activate_rank`; отдельного хранилища ручной
даты у истории или `Person` нет. Изменение этого поля запускает rebuild владельца строки, а
refill воспроизводит его значение. Разряд, поступающий от OrientBy без protocol line, не
создаёт ни `RankFact`, ни элемент истории.

### Индексы истории

| Индекс | Назначение |
|--------|------------|
| `(person_id, achieved_on, id)` | Хронологическое чтение всей истории одного спортсмена. |
| `(protocol_line_id)` | Связь с источником, проверка и удаление/пересчёт после изменения строки. |

Прямые ID нужны для чтения истории, а не для отдельной фильтрации истории, поэтому для них
не добавляются дополнительные performance-индексы. Индексы, необходимые foreign keys, создаются
схемой хранения автоматически либо переиспользуют уже существующие.

## Вход и выход расчёта

| Объект | Роль |
|--------|------|
| `RankFact` | Нормализованный допустимый факт из protocol line: спортсмен, выполненный `Rank`, дата event и дата ручной активации из `activate_rank`. Массовость и статус вне конкурса отфильтрованы collector до создания объекта. |
| `Person.birthday` | Данные aggregate `Person`, передаваемые калькулятору отдельно от facts для возрастного правила. |
| `CalculatedRankHistory` | Результат Domain-калькулятора: упорядоченные элементы `PersonRankHistory` и снимок текущего состояния `Person`. |

Это чистые доменные данные: они не знают об Eloquent, очередях, HTTP или persistence.

## Инварианты

1. Внутри Domain и Application текущий разряд, история и расчёт используют только cases `Rank`; на внешних границах допустим только его backed value или внешний текст, который нормализуется в enum.
2. У истории всегда есть protocol line того же спортсмена; refill не оставляет записи без источника.
3. `distance_id`, `event_id` и `competition_id` истории соответствуют неизменяемой на момент rebuild цепочке источника protocol line.
4. В результате одного rebuild текущие поля `Person` и вся его история соответствуют одной дате расчёта.
5. Две одинаковые последовательности входных фактов и дата расчёта дают одинаковые историю и состояние.
6. История может быть большой; обычный list `Person` не загружает её relation.
7. `activated_on` истории соответствует `activate_rank` её protocol line; только это поле может вручную изменить дату применения выполнения.
