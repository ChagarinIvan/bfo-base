# Контракт: текущий разряд в списке спортсменов

## Получение спортсменов

`GET /api/v1/persons`

Существующий список спортсменов дополняется текущим разрядом и фильтром по нему.

### Параметры запроса

| Параметр | Тип | Обязателен | Описание |
|----------|-----|------------|----------|
| `clubId` | integer | нет | Существующий фильтр по активному клубу. |
| `rankId` | integer | нет | Backed value case `Rank`. Значение `0` выбирает спортсменов без действующего разряда. |
| `page` | integer | нет | Существующая пагинация. |
| `perPage` | integer | нет | Существующая пагинация. |

Недопустимое значение `rankId` получает обычную валидационную ошибку API. Отсутствующий
параметр не фильтрует список.

### Поле ответа

Каждый элемент списка получает обязательное поле `rankId` — integer backed value case `Rank`,
включая `0` для спортсмена без действующего разряда. Отображаемая строка
определяется по [справочнику разрядов](./api-ranks.md).

```json
{
  "id": "42",
  "lastname": "Іваноў",
  "firstname": "Іван",
  "birthYear": 2001,
  "rankId": 6
}
```

Поля impressions и заголовки пагинации сохраняют существующий контракт.

## История разрядов

Существующие Blade-страницы истории сохраняют URL и пользовательский сценарий. Они читают
историю через новый read use case и для каждого элемента показывают тип изменения, источник
и даты из [модели данных](../data-model.md). История использует прямые ID соревнования,
event и дистанции для глубоких ссылок и batch-loading актуальных названий. Новый SPA/API
контракт истории не создаётся в рамках этой фичи.
