# Проверка вручную

1. Применить миграции и загрузить новый протокол с II, III, Iю, IIю и IIIю. Дата активации у новых строк отсутствует.
2. Привязать строки к спортсменам и открыть историю: выполнение видно, действующий разряд до срока не меняется.
3. Запустить ежедневное задание датой до срока и в день срока; в день срока история получает рассчитанную дату, а текущий разряд меняется.
4. Для отдельной строки указать ручную дату в пределах месяца. Проверить, что она сохраняется после срока. Попробовать дату до соревнования через POST и PUT: оба запроса дают 422.
5. Очистить ручную дату до срока и проверить возврат ожидания. Пересчитать старую строку с датой активации: дата остаётся прежней.
6. Создать три подходящих старта без явного IIIю и проверить немедленное действие вычисленного разряда.

Узкие проверки: `RankCalculatorTest`, API request-тесты активации и feature-тест ежедневного пересчёта. Итоговая проверка: `composer test`, `composer stan`, `composer cs`, `composer rector -- --dry-run`, `npm run ci` и запуск приложения согласно правилам репозитория.
