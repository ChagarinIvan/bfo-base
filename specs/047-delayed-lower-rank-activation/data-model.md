# Модель данных

## `protocol_lines`

Новый `delayed_rank_activation BOOLEAN NOT NULL DEFAULT FALSE`. `false` означает историческое правило; `true` означает месячную активацию для пяти целевых разрядов. Значение присваивается при создании новой строки. `activate_rank DATE NULL` остаётся датой ручной активации либо старой сохранённой датой. Автоматическая дата в ней не сохраняется, чтобы отмена ручной даты снова восстановила правило.

## `person`

Новый `next_rank_activation_on DATE NULL`, индексированный для ежедневного отбора. Это производное состояние от фактов спортсмена, ближайшая дата ещё не наступившей автоматической либо будущей ручной активации нового целевого выполнения. Метод пересчёта меняет поле одновременно с текущим разрядом и историей.

## `RankFact`, `PersonRankState`

`RankFact` получает `delayedActivation: bool = false`, выставляемый коллектором по строке. Синтетический IIIю создаётся с явной датой третьего старта и `false`. `PersonRankState` получает `nextActivationOn: ?Carbon`; при отсутствии ожидающих сроков это `null`.

## Инварианты

- История нового целевого факта до срока: `activated_on = NULL`, `finished_on = NULL`.
- После срока: `activated_on = achieved_on + 1 calendar month`, а срок действия рассчитывается от этой даты.
- Если `activate_rank` задана, она имеет приоритет над вычисленным сроком.
- `next_rank_activation_on` равна минимуму будущих дат активации новых целевых фактов: ручной даты, если она задана, иначе месячного срока. В день срока она уже не входит в будущие.
- Старые строки и строки других разрядов не меняют правило от значения `delayed_rank_activation = false`.
