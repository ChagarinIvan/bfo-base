# Data Model: Асинхронная проверка разрядов по списку

## RankCheck

Представляет одну принятую загрузку и её жизненный цикл.

| Поле | Назначение | Ограничения |
|---|---|---|
| `id` | Идентификатор запуска | Уникальный, внешний API-safe ID |
| `createdBy` | Администратор-владелец | Обязателен |
| `status` | Состояние запуска | Только `PARSING`, `READY`, `FAILED`; по умолчанию `PARSING` |
| `sourcePath` | Ссылка на сохранённый входной файл | Не возвращается публично; удаляется по retention |
| `errorMessage` | Безопасное описание ошибки | Только для разрешённого администратора |
| `createdAt` | Время создания | Обязательно |
| `updatedAt` | Время последнего изменения запуска | Обновляется при создании и каждом изменении статуса/результата |

### State transitions

```text
PARSING ──success──> READY
   │
   └──failure──────> FAILED
```

Финальные состояния неизменяемы. Повторная обработка завершённого запуска не выполняется.

## RankCheckRow

Снимок одной принятой строки списка. Строки имеют `rankCheckId` и `position`; уникальность
внутри запуска определяется позицией, а не ФИО, поэтому дубликаты входа сохраняются.

### Значения из файла

`group`, `name`, `club`, `rank`, `number` (nullable), `year` (nullable).

### Идентификация и база

`personId` (nullable), `databaseName`, `databaseClub`, `databaseRank`, `databaseYear` —
значения найденной активной персоны на момент выполнения.

### Итоговые признаки

`hasPerson` — спортсмен найден; `isEqual` — одновременно совпадают ФИО, клуб, год и разряд.
Отсутствующий актуальный разряд считается совпадением с входным значением без разряда.
Группа и стартовый номер отображаются, но не входят в исторический общий признак `isEqual`.

## Read model

API возвращает запуск с `status`, `created`/`updated` Impression и отдельными пагинируемыми
`rows`; строки доступны только в `READY`. Для `PARSING` возвращается мета-информация без
неполных строк, для `FAILED` — безопасная ошибка без частичного результата. Для готового запуска
rows endpoint возвращает стандартные pagination headers; выборка строк сортируется по `position`.

## Retention

Ежедневная плановая очистка удаляет запуски, созданные более 24 часов назад, их строки и исходные
файлы. Старые `PARSING`-запуски считаются зависшими и также удаляются; более новые запуски
сохраняются.
