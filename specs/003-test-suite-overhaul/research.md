# Research: Переработка тестового набора

**Date**: 2026-08-27 | **Feature**: 003-test-suite-overhaul

Разведка по трём направлениям: (1) скорость, (2) чистота вывода, (3) покрытие. Все факты сверены с
текущим состоянием репозитория (после 001/002: PHP 8.5, Laravel 13.26.1, PHPUnit 13.3).

---

## Факты на входе (замер репозитория)

- Тесты: **112 файлов**, ~237 тестов. Прогон на **реальном MySQL** (`.env.testing`:
  `DB_CONNECTION=mysql`, база `bfo_base`), **65 миграций**.
- БД-стратегия: **50 файлов используют `RefreshDatabase`**, `DatabaseTransactions` — 0, `DatabaseMigrations` — 0.
  Значит: `RefreshDatabase` уже гоняет `migrate:fresh` **один раз** за прогон и оборачивает **каждый тест
  в транзакцию с откатом** → «полный перенакат между каждым тестом» по факту НЕ происходит; откат уже есть.
- `phpunit.xml`: `CACHE=array`, `SESSION=array`, `QUEUE=sync`, `BCRYPT_ROUNDS=4` — базовые ускорения уже
  включены. Соединение БД в `phpunit.xml` не переопределено → берётся из `.env.testing` (MySQL).
- MySQL-специфичный SQL в целевом коде: `DB::raw("CONCAT(...)")` (PersonsService), multi-table `DELETE ...
  INNER JOIN ... ORDER BY` (ranks, чинили в 001) — это блокер для наивного перехода на SQLite.
- Вывод прогона: стабильно **«PHPUnit Notices: 3»** (точный список — задача Phase реализации US2);
  PHP deprecations на 8.5 в 001 были устранены (config PDO), но полный аудит с `--display-deprecations`
  ещё не делался.
- Целевой код для US3: **42 `Application\...Service`**; доменные сервисы `Domain/Rank/*` (чистые
  чекеры/валидаторы: `JuniorRankAgeValidator`, `*RankChecker`, `PreviousCompletedRankFiller`, …) и
  `Domain/Cup/*` — идеальные дешёвые юнит-цели. Уже есть ~37 файлов тестов, касающихся rank/cup.
- Легаси (не покрываем): слои `app/Repositories`, `app/Services` (конституция, принцип I/IV).

---

## Decision A — Скорость: параллельный прогон + гигиена фикстур, MySQL сохраняем

- **Decision**: Основной рычаг ускорения — **параллельный прогон** (`php artisan test --parallel`,
  paratest) с отдельной тест-БД на процесс; плюс **гигиена фикстур** (`make()` вместо `create()` там, где
  БД не нужна; меньше персистируемых строк; общие данные — экономно). MySQL как тест-СУБД **сохраняем**.
- **Rationale**: `RefreshDatabase` уже даёт транзакционный откат, поэтому «обернуть в транзакцию» —
  почти сделано; крупный запас — в распараллеливании (multicore) и в сокращении обращений к БД.
  Переезд на SQLite :memory: (самый быстрый вариант) **отвергнут как рискованный**: код использует
  MySQL-специфичный SQL (`CONCAT`, multi-table DELETE+JOIN), который на SQLite не работает или ведёт себя
  иначе → это меняло бы то, что тесты реально проверяют, и грозило ложными зелёными/красными.
- **Проверки**: подтвердить, что `migrate:fresh` идёт один раз; замерить вклад параллелизма; убедиться,
  что параллельные процессы не делят одну БД (иначе гонки).
- **Alternatives**:
  - **SQLite :memory:** — кратно быстрее, но несовместим с MySQL-специфичным SQL → отвергнут (риск
    изменения смысла тестов).
  - **Только гигиена фикстур без параллелизма** — даёт меньший выигрыш; берём в дополнение, не вместо.
  - **Схема-дамп (`--schema-path`) вместо 65 миграций** — ускоряет разовый `migrate:fresh`; рассмотреть
    как дополнительную меру, если стартовая миграция окажется заметной долей времени.

## Decision B — Критерий ускорения (SC-001) — БЕЗ числового порога

> **Уточнено 2026-08-27 (clarify):** жёсткий порог не задаём.

- **Decision**: Критерий — полное время прогона **заметно меньше** базовой линии, оценка прямым
  сравнением замеров «до/после» (`time composer test`). Конкретная цифра приёмку не блокирует.
- **Rationale**: Владелец выбрал гибкую оценку вместо фиксированного процента — время сильно зависит от
  железа/CI, а параллелизм даёт разный выигрыш. Фиксируем базовую линию и демонстрируем значимое
  сокращение фактом.
- **Alternatives**: `≥30%` (исходный дефолт) — отвергнут в пользу гибкой оценки; фиксированные секунды —
  зависят от окружения.

## Decision C — Чистота вывода: аудит и починка по первопричине

- **Decision**: Прогнать `phpunit --display-deprecations --display-notices --display-warnings`, собрать
  полный список, устранить **первопричину** каждого (адаптация тестового/прикладного вызова под PHP 8.5 /
  PHPUnit 13 / Laravel 13), без подавления. Известные ныне: 3 PHPUnit Notices.
- **Rationale**: FR-006/SC-002 требуют ноль предупреждений без замалчивания. Типовые источники в PHPUnit
  13: устаревшие способы объявления data-provider/тестов, аннотации вместо атрибутов, нестрогие ассерты.
- **Alternatives**: `failOnDeprecation`/baseline-подавление — отвергнуто (маскирует, а не чинит).

## Decision D — Покрытие: широкий охват целевого слоя + характеризация ranks/cups

> **Уточнено 2026-08-27 (clarify):** охват — **широкий по целевому слою**, не только ranks/cups.

- **Decision**: Систематически покрыть целевую архитектуру (широко):
  - **Доменные сервисы** `Domain/Rank/*`, `Domain/Cup/*` — чистая логика, юнит-тесты без БД (быстрые).
  - **Application-сервисы** (42 шт.) — сценарии оркестрации, зависимости через моки интерфейсов.
  - **Сложные выборки** в Eloquent-репозиториях целевого слоя (`app/Infrastructure/...Repository`) — на
    репрезентативных данных.
  - **Интеграционные** request/API-тесты контроллеров (частично покрывают легаси через публичное поведение).
  - **ranks/cups** — характеризационные тесты, фиксирующие текущее поведение (baseline); проверяем их
    осмысленность намеренной поломкой логики (должны падать).
- **Rationale**: Соответствует FR-007…FR-011 и принципам I/III/IV конституции; ranks/cups — критичны и
  рискованны (сложная доменная логика разрядов, сводные расчёты кубков).
- **Не покрываем**: `app/Repositories`, `app/Services` (легаси), тривиальные DTO/геттеры.
- **Alternatives**: Гонка за % покрытия — отвергнута (FR-011 «в разумных пределах»).

## Итоговый порядок (для tasks)

1. **US1 — скорость**: замер базовой линии → подтвердить/настроить транзакционный откат и одноразовый
   migrate → включить параллельный прогон (отдельные БД на процесс) → гигиена фикстур → замер «после»
   заметно меньше «до».
2. **US2 — чистота**: аудит `--display-deprecations/--display-notices/--display-warnings` → починка
   первопричин → ноль предупреждений.
3. **US3 — покрытие**: доменные сервисы Rank/Cup (юнит) → Application-сервисы → сложные выборки репо →
   интеграционные API/контроллеры → характеризация ranks/cups (baseline).

## Открытые вопросы

- Порог SC-001 — **снят** (уточнение 2026-08-27): оценка гибкая, сравнением замеров до/после.
- Точный список deprecations/notices — снимается прогоном `--display-*` на шаге реализации US2.
- Реалистичность SQLite для части чистых unit-тестов (без MySQL-SQL) — можно рассмотреть точечно, но по
  умолчанию тест-СУБД единая (MySQL), чтобы не раздваивать поведение.
