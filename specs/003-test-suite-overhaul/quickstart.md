# Quickstart: валидация переработки тестов

**Feature**: 003-test-suite-overhaul | **Date**: 2026-08-27

Руководство по проверке трёх направлений. Решения — в [research.md](./research.md), список шагов — в
plan.md / tasks.md.

## Предпосылки

- Ветка `003-test-suite-overhaul` (от `002-modernize-codebase`; стек PHP 8.5 / Laravel 13).
- Активен PHP 8.5 (`php -v` → 8.5.x; при необходимости `export PATH="/opt/homebrew/bin:$PATH"`).
- Доступен MySQL для тестов (`.env.testing`); для `--parallel` — возможность создать БД на процесс.

## Базовая линия (до изменений)

```bash
# зафиксировать время и вывод «до» (одинаковое окружение, без сторонней нагрузки)
for i in 1 2 3; do time composer test; done   # взять медиану из 3 прогонов
composer test -- --display-deprecations --display-notices --display-warnings   # снять полный список предупреждений
composer stan && composer cs && composer rector -- --dry-run
```

## Гейты после КАЖДОГО шага (DoD)

## Проверки по направлениям

### US1 — скорость

Базлайн: `time composer test` ≈ **193с** (I/O-bound, 95% — ожидание MySQL). Транзакционный откат уже
активен (`RefreshDatabase`), `migrate:fresh` идёт один раз (2.85с), фикстуры минимальны — эти оси уже
оптимальны.

**Безопасный выигрыш — durability tuning тест-MySQL (−20%, → ~153с):**

```sql
-- применить на тест-MySQL (dev-контейнер), ускоряет коммиты за счёт снятия durability
SET GLOBAL innodb_flush_log_at_trx_commit = 0;
SET GLOBAL sync_binlog = 0;
```

Персистентно — добавить в `my.cnf` тест-MySQL (секция `[mysqld]`):
```ini
innodb_flush_log_at_trx_commit = 0
sync_binlog = 0
```

> ⚠️ **Только для тестовой БД!** Снятие durability допустимо для эфемерных тест-данных, но НЕ для прод.

**Отвергнуто как неэффективное** (проверено): параллель (`--parallel` — упор в единственный MySQL, 0
ускорения + хрупкость на хардкод-ID), `mysql_native_password` (без разницы), урезание фикстур (уже
минимальны), «держать app поднятым» (буткап ~8с CPU — не узкое место). Кратное ускорение потребует
параллели с ID-рефакторингом тестов ИЛИ смены тест-СУБД — вынесено в будущий проект.

- **Критерий**: `time composer test` с tuning **устойчиво меньше** базлайна (то же окружение); набор
  зелёный и стабильный.

### US2 — чистота вывода

- `composer test -- --display-deprecations --display-notices --display-warnings` → **ноль** deprecations,
  notices, warnings.
- Каждое устранено правкой первопричины (тест или устаревший вызов), НЕ подавлением/baseline/игнором.
- Тесты остаются зелёными.

### US3 — покрытие

- Новые тесты только для целевой архитектуры: `tests/Domain/**` (сервисы Rank/Cup и др.),
  `tests/Application/**` (сервисы через моки интерфейсов), сложные выборки репозиториев целевого слоя,
  `tests/Bridge/Laravel/Http/**` (интеграционные API/контроллеры).
- Ноль новых тестов на легаси (`app/Repositories`, `app/Services`).
- **ranks/cups**: добавлены характеризационные тесты, фиксирующие текущее поведение; проверка
  осмысленности — намеренно сломать логику ranks/cups → соответствующие тесты падают, затем откатить.
- Осмысленность нового теста: до добавления ключевой сценарий не покрыт; новый тест зелёный и падает при
  поломке проверяемой логики.

## Критерий приёмки фичи (из spec.md)

- SC-001: медиана из 3 прогонов устойчиво меньше медианы базовой линии (то же окружение; вне шума
  измерения) при неизменном/большем числе тестов.
- SC-002: ноль deprecations/notices/warnings, ничего не скрыто подавлением.
- SC-003: ранее зелёные тесты зелёные; стабильность при повторных/переупорядоченных прогонах.
- SC-004: характеризационные тесты ranks/cups падают при намеренной поломке логики.
- SC-005: новое покрытие только для целевой архитектуры и интеграционных тестов; ноль тестов на легаси.
- SC-006: каждый шаг — зелёные гейты + отдельный откатываемый коммит; поведение неизменно.
