# Спецификация фичи: удаление FAQ-раздела

**Ветка фичи**: `006-remove-faq`

**Создано**: 2026-08-31

**Статус**: Черновик

**Входные данные**: описание пользователя: "Удалить FAQ-раздел из нового SPA-приложения и старого Blade, очистить legacy Blade-шаблоны, связанные переводы и API, если у них нет другого использования."

## Уточнения

### Сессия 2026-08-31

- Q: Если аудит не найдёт потребителей у старого API endpoint, нужно ли удалять сам endpoint и его реализацию, или удаляем только FAQ-документацию и связанные с ней маршруты? → A: Удалять подтверждённо неиспользуемые endpoint и их реализацию; используемые сохранять.
- Q: Если после удаления FAQ в меню справки не останется других пунктов, нужно ли полностью убрать само меню справки из SPA и legacy Blade? → A: Полностью удалить пустое меню справки.
- Q: Должен ли аудит считать потребителями API только использования внутри репозитория, или нужно учитывать также внешних клиентов и публичную документацию вне проекта? → A: Учитывать только найденные ссылки внутри репозитория.

## Пользовательские сценарии и тестирование *(обязательно)*

### Пользовательская история 1 — убрать FAQ из навигации (приоритет: P1)

Пользователь видит только актуальные разделы приложения и не получает ссылок на
устаревший FAQ или страницу описания API.

**Почему этот приоритет**: устаревшие ссылки создают ложное ожидание поддержки и
оставляют в интерфейсе раздел, который больше не является частью продукта.

**Независимая проверка**: открыть SPA и legacy Blade-страницу с авторизованным
пользователем и убедиться, что в навигации отсутствуют FAQ и API FAQ, а остальные
пункты меню продолжают работать.

**Сценарии приёмки**:

1. **Given** авторизованный пользователь открыл SPA, **When** он раскрывает меню
   справки, **Then** в меню отсутствуют пункты FAQ и API.
2. **Given** пользователь открыл legacy Blade-страницу, **When** он просматривает
   навигацию, **Then** в ней отсутствуют FAQ и API FAQ, а соседние разделы не
   изменились.
3. **Given** неавторизованный пользователь, **When** он открывает SPA или legacy
   страницу, **Then** он не видит FAQ-ссылки ни в одном доступном меню.

---

### Пользовательская история 2 — закрыть устаревшие FAQ-страницы (приоритет: P1)

Пользователь не может открыть удалённые FAQ-страницы по старым прямым адресам.

**Почему этот приоритет**: удаление только ссылок оставило бы устаревший контент
доступным по закладкам, поисковой выдаче или внешним ссылкам.

**Независимая проверка**: запросить прежние адреса FAQ и API FAQ и проверить, что они
не возвращают удалённые страницы, при этом существующие несвязанные адреса
продолжают отвечать как раньше.

**Сценарии приёмки**:

1. **Given** пользователь запрашивает `/faq`, **When** приложение обрабатывает
   запрос, **Then** FAQ-страница не отображается и приложение возвращает свой
   стандартный ответ для отсутствующего адреса.
2. **Given** пользователь запрашивает `/faq/api`, **When** приложение обрабатывает
   запрос, **Then** страница описания API не отображается и приложение возвращает
   свой стандартный ответ для отсутствующего адреса.
3. **Given** пользователь запрашивает любой другой существующий маршрут, **When**
   приложение обрабатывает запрос, **Then** результат работы этого маршрута не
   меняется из-за удаления FAQ.

---

### Пользовательская история 3 — удалить неиспользуемые остатки FAQ (приоритет: P2)

Разработчик поддерживает кодовую базу без мёртвых FAQ-контроллеров, шаблонов,
навигационных флагов и переводов.

**Почему этот приоритет**: удаление связанных остатков предотвращает повторное
появление FAQ через случайное переиспользование старых классов и ключей.

**Независимая проверка**: выполнить поиск по репозиторию после изменения и убедиться,
что удалённые FAQ-артефакты не имеют ссылок, а фактически используемые общие
компоненты и API не затронуты.

**Сценарии приёмки**:

1. **Given** удаление FAQ завершено, **When** разработчик проверяет навигационные
   модели и данные legacy-навигации, **Then** там нет FAQ-пунктов и специальных
   FAQ-флагов маршрута.
2. **Given** удаление FAQ завершено, **When** разработчик проверяет шаблоны,
   контроллеры и переводы, **Then** неиспользуемые FAQ-артефакты отсутствуют.
3. **Given** старый API endpoint используется не только FAQ-страницей, **When**
   выполняется очистка, **Then** endpoint сохраняется; удаляются только endpoints,
   которые после проверки не имеют других потребителей.

## Граничные случаи

- Прямой переход по `/faq` и `/faq/api` должен обрабатываться одинаково независимо
  от авторизации и языка интерфейса.
- Удаление FAQ не должно удалить общие ключи переводов, которые используются
  другими страницами.
- Удаление FAQ API-документации не должно автоматически удалять реальные API
  endpoints, если на них ссылаются другие страницы, интеграции или тесты.
- Legacy navbar не должен потерять соседние разделы или изменить их доступность.
- В SPA не должно остаться переходов на удалённые FAQ-адреса через fallback,
  меню или тестовые фикстуры.

## Требования *(обязательно)*

### Функциональные требования

- **FR-001**: Система ДОЛЖНА удалить FAQ и API FAQ из навигации нового SPA.
- **FR-002**: Система ДОЛЖНА удалить FAQ и API FAQ из legacy Blade-навигации.
- **FR-002a**: Если после удаления FAQ в меню справки не остаётся других пунктов,
  система ДОЛЖНА удалить это пустое меню из SPA и legacy Blade.
- **FR-003**: Система ДОЛЖНА прекратить публикацию страниц по адресам `/faq` и
  `/faq/api`; прямой запрос к ним ДОЛЖЕН получать стандартный ответ для
  отсутствующего маршрута.
- **FR-004**: Система ДОЛЖНА удалить шаблоны и контроллеры, предназначенные только
  для FAQ и API FAQ.
- **FR-005**: Система ДОЛЖНА удалить специальные данные и флаги навигации,
  предназначенные только для определения FAQ-маршрутов.
- **FR-006**: Система ДОЛЖНА удалить переводы, используемые только удалёнными FAQ
  страницами и их пунктами навигации.
- **FR-007**: Перед удалением кода, связанного с API, система ДОЛЖНА проверить
  его использование по всему репозиторию; внешние интеграции без следов в
  репозитории в аудит не включаются. Фактически используемые API endpoints
  ДОЛЖНЫ оставаться доступными, а подтверждённо неиспользуемые endpoints и их
  реализации ДОЛЖНЫ быть удалены.
- **FR-008**: Система ДОЛЖНА сохранять все записи навигации, маршруты, переводы и
  поведение API, не связанные с FAQ.
- **FR-009**: Система ДОЛЖНА включать автоматические регрессионные проверки
  отсутствия навигации FAQ и недоступности удалённых legacy-страниц.
- **FR-010**: Система ДОЛЖНА не оставлять ссылок на удалённые FAQ-маршруты, контроллеры,
  шаблоны или ключи переводов, кроме спецификации фичи и документации миграции/
  истории, где удаление явно описано.

## Критерии успеха *(обязательно)*

### Measurable Outcomes

- **SC-001**: 100% проверок навигации SPA и legacy после изменения не содержат
  записей FAQ или API FAQ.
- **SC-002**: 100% прямых запросов к `/faq` и `/faq/api` получают стандартный
  ответ для отсутствующего маршрута и не отображают содержимое FAQ.
- **SC-003**: Поиск по репозиторию не находит в активном коде ссылок на удалённые FAQ
  контроллеры, шаблоны, флаги маршрутов или ключи переводов, используемые только FAQ.
- **SC-004**: Все существующие автоматические тесты несвязанных с FAQ маршрутов
  остаются зелёными после удаления.
- **SC-005**: Ни один фактический API endpoint не удаляется, если по результатам
  аудита внутри репозитория у него есть хотя бы один потребитель вне удаляемой
  страницы документации FAQ.

## Допущения

- Удаление является намеренным и постоянным как для навигации SPA, так и для
  интерфейса legacy Blade.
- Перенаправление или замещающая страница справки не требуются; удалённые адреса
  используют стандартное поведение приложения для отсутствующего маршрута.
- Содержимое FAQ не переносится в новый центр помощи в рамках этой фичи.
- «API FAQ» — это legacy-страница документации и её маршрут; фактические API
  endpoints удаляются вместе с реализациями только после подтверждения их
  неиспользования поиском по всему репозиторию. Внешние клиенты без ссылок в
  репозитории не учитываются.
- Существующие авторизация, инфраструктура локализации и несвязанная навигация
  используются без изменений.
