# Модель данных: удаление FAQ-раздела

Фича: 006-remove-faq

Эта фича не добавляет сохраняемые сущности или миграции данных. Она удаляет
артефакты представления и маршрутизации. Следующий перечень удалений определяет
авторитетную область реализации.

## Перечень артефактов представления FAQ

| Область | Существующий артефакт | Целевое состояние |
|---|---|---|
| Навигация SPA | authenticatedHelpNavigation, spa.nav.faq, spa.nav.api | Нет записей FAQ/API и пустого меню справки |
| Legacy-навигация | Выпадающее меню справки и импорты FAQ action в resources/views/layouts/navbar.blade.php | Выпадающее меню справки удалено; остальные меню без изменений |
| Legacy-маршрутизация | Группа маршрутов faq в WebRoutesServiceProvider | Маршруты /faq и /faq/api отсутствуют |
| Legacy actions | ShowFaqAction, ShowApiFaqAction | Файлы удаляются, если других потребителей нет |
| Legacy-представления | resources/views/faq/index.blade.php, api.blade.php | Файлы удалены |
| Состояние маршрута | isFaqRoute, isFaqApiRoute и записи данных navbar | Удалено после аудита потребителей |
| Переводы | app.faq.*, app.api.* и ключи навигации FAQ, используемые только FAQ | Удалены только если не используются |

## Аудит использования API

В реализации нужно классифицировать каждый старый endpoint, на который ссылалась
удаляемая страница API FAQ:

1. Сохранить, если его используют маршрут, тест, фронтенд, интеграция или
   документированный внешний контракт вне удаляемой страницы.
2. Удалять только если потребителей не осталось, а маршрут/контроллер представляет
   собой исключительно мёртвый остаток эпохи FAQ.
3. Зафиксировать сохранённые и удалённые кандидаты в описании реализации/PR.

Записи базы данных, миграции и доменные сущности не изменяются.
