# План реализации: удаление FAQ-раздела

**Ветка**: `006-remove-faq` | **Дата**: 2026-08-31 | **Спецификация**: [spec.md](spec.md)

**Входные данные**: спецификация фичи из `specs/006-remove-faq/spec.md`

## Краткое содержание

Удалить устаревший FAQ и страницу описания API из SPA и legacy Blade, включая
маршруты, шаблоны, контроллеры, навигационные записи, состояние маршрутов и
переводы, используемые только FAQ. Перед удалением любого фактического API
endpoint выполнить аудит использования внутри репозитория; подтверждённо
неиспользуемые endpoints и их реализации удалить, остальные сохранить.

## Технический контекст

**Язык/версия**: PHP 8.5; TypeScript 5.x; Vue 3

**Основные зависимости**: Laravel 13, Vue Router, PrimeVue, PHPUnit, Vitest

**Хранилище**: отсутствует; фича удаляет только код представления и маршрутизации

**Тестирование**: feature/request-тесты PHPUnit; Vitest; линтер, проверка типов и сборка фронтенда

**Целевая платформа**: веб-приложение со SPA и страницами legacy Blade, отображаемыми на сервере

**Тип проекта**: веб-приложение Laravel с Vue SPA

**Цели производительности**: без регрессий в поведении существующих маршрутов; без новой работы во время выполнения

**Ограничения**: сохранять навигацию, маршруты, переводы и фактические API endpoints, не связанные с FAQ; учитывать только использования внутри репозитория; перенаправление на замену не требуется

**Масштаб/область**: две FAQ-страницы, две системы навигации, общее состояние FAQ в базовых action-классах, переводы только для FAQ и любой подтверждённо неиспользуемый legacy API-код

  представления, представление SPA и переводы; новый слой Application/Domain не нужен.
- Отсутствие расширения legacy: ПРОЙДЕНО — новые классы и сервисы не вводятся.

  сохранить все несвязанные проверки.
- Стиль и стек: ПРОЙДЕНО — использовать существующие соглашения PHP 8.5/Laravel 13

- Производительность: ПРОЙДЕНО — удаление маршрутов и представлений не может добавить

**Решение по структуре**: это межслойное удаление в существующем веб-приложении
Laravel. Ограничить изменение потребителями FAQ и общим состоянием базовых
actions, которое станет неиспользуемым. Не создавать замещающие абстракции или
новые сервисы. Аудит использования API определит, можно ли также удалить код
старых API-контроллеров.

Нарушений конституции нет.
