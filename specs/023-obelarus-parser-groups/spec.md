# Спецификация фичи: корректный импорт групп OBelarus.net

**Ветка фичи**: `023-obelarus-parser-groups`  
**Создано**: 2026-09-13  
**Статус**: Draft

## Входная проблема

Production-протокол `storage/tests/2026/20260911.htm` не импортирует корректные
группы участников. Из-за этого результаты спортсменов не связываются с ожидаемыми
группами и не могут использоваться как обычные результаты соревнования.

## Пользовательские сценарии и тестирование

### История 1 — Импорт результатов в правильные группы (P1)

Администратор импортирует OBelarus.net-протокол от 11 сентября 2026 года и получает
результаты, у которых группа соответствует заголовку исходного протокола.

**Почему P1**: без группы импорт результатов непригоден для публикации и дальнейшей
обработки.

**Независимая проверка**: запустить тест `OBelarusNetParserTest` на реальном fixture
`2026/20260911.htm`.

**Сценарии приемки**:

1. **Дано** обычный участник группы М21, **когда** разбирается fixture, **тогда** у
   результата сохранены группа М21, персональные данные, номер, время и место.
2. **Дано** обычные участники как минимум двух других групп, **когда** разбирается
   fixture, **тогда** каждый результат сохраняет группу из своего заголовка, а не
   группу предыдущего или следующего блока.
3. **Дано** снятый участник без времени, **когда** разбирается fixture, **тогда**
   сохраняются его персональные данные, номер и группа, а время и место отсутствуют.

### История 2 — Сохранение совместимости OBelarus.net (P2)

Администратор продолжает импортировать ранее поддерживаемые OBelarus.net-протоколы без
изменения уже корректно разобранных данных.

**Независимая проверка**: существующие fixture-кейсы `OBelarusNetParserTest` проходят
вместе с новым fixture.

**Сценарии приемки**:

1. **Дано** существующие OBelarus.net fixtures, **когда** запускается набор parser-тестов,
   **тогда** прежние ожидаемые результаты не меняются.

### Граничные случаи

- Заголовок группы содержит вложенный HTML-элемент перед текстом группы.
- В одном протоколе присутствуют женские, мужские и открытые группы.
- Снятый участник представлен без времени и места.
- Пустой блок группы не создаёт фиктивного результата и не влияет на следующую группу.

## Требования

- **FR-001**: импорт MUST определять название группы из каждого блока результатов
  fixture `20260911.htm`.
- **FR-002**: импорт MUST сохранять группу М21 для обычного участника этой группы.
- **FR-003**: импорт MUST сохранять корректные группы как минимум для двух обычных
  участников из других групп fixture.
- **FR-004**: импорт MUST сохранять группу снятого участника без создания времени или
  места.
- **FR-005**: regression-тест MUST использовать production fixture
  `storage/tests/2026/20260911.htm` и не заменять существующие parser fixtures.
- **FR-006**: изменение MUST сохранять результаты существующих OBelarus.net parser-тестов.

## Ключевые сущности

- **Группа результата**: категория спортсмена, указанная в заголовке блока протокола.
- **Строка протокола**: результат участника с персональными данными, категорией,
  стартовым номером, временем и местом, если они есть.

## Критерии успеха

- **SC-001**: все выбранные обычные участники и снятый участник fixture импортируются
  с ожидаемыми группами.
- **SC-002**: снятый участник импортируется без времени и места.
- **SC-003**: 100% существующих и нового OBelarus.net parser-тестов проходят.
- **SC-004**: импорт fixture не создаёт результатов с пустой или неверно сдвинутой
  группой.

## Допущения

- Fixture `20260911.htm` является репрезентативным production-протоколом OBelarus.net.
- Исправление ограничено существующим OBelarus.net import flow; миграции, API и SPA не
  требуются.
- «Снятый» означает строку fixture без времени и места, независимо от текстовой
  причины отсутствия результата.
