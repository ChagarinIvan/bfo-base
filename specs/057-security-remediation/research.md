# Research. Обновление безопасности

Проверено 2026-11-23. Наблюдения о репозитории и рекомендации поставщиков не подтверждают состояние Lightsail.

## Laravel и Composer

**Решение.** Обновить `laravel/framework` в ветке 13.x, начиная с проверенного стабильного 13.43.0. Сохранить проверку production-зависимостей и повторить её после обновления.

**Основание.** В lock-файле 13.39.0. `composer audit --locked --no-dev --no-interaction` подтвердил CVE-2026-128083. Предупреждение закрыто в 13.40.0. В 13.43.0 также закрыты дополнительные предупреждения поставщика. Предпочтителен целевой update с минимальными изменениями транзитивных версий. Игнорирование advisory и широкий update всех пакетов без необходимости отклонены. [Advisory Laravel](https://github.com/advisories/GHSA-63hm-g96r-2m2q) [Релиз 13.43.0](https://github.com/laravel/framework/releases/tag/v13.43.0) [Advisories Laravel](https://github.com/laravel/framework/security/advisories)

## PHP

**Решение.** Использовать PHP 8.5.13 в CI и образе и сохранить существующую настройку `session.upload_progress.enabled=0`. Сверить и обновить действующий PHP Lightsail отдельно, включая FPM и фоновые процессы.

**Основание.** Для двух заявленных CVE минимальный исправленный релиз ветки 8.5 — 8.5.12, уже зафиксированный в репозитории фичей 052. PHP 8.5.13 от 19 ноября — актуальный security-релиз ветки на дату проверки с официальным FPM-тегом. Переход на PHP 8.6 здесь не нужен. Для PHP из репозитория дистрибутива статус определяется по бюллетеню конкретного пакета и его источнику. [AWS PHP](https://docs.aws.amazon.com/lightsail/latest/userguide/amazon-lightsail-update-php-security-vulnerabilities.html) [PHP 8.5.13](https://www.php.net/releases/8_5_13.php) [Официальные образы](https://raw.githubusercontent.com/docker-library/official-images/master/library/php)

## Ядро, ОС и выкат

**Решение.** Сопоставить загруженное ядро и пакет с таблицей Canonical по точным release и flavor. Для затронутого экземпляра установить vendor patch, перезагрузить и сверить работающее ядро. Если подтвердится Ubuntu 20.04, предпочесть отдельный Ubuntu 24.04 с репетицией восстановления и согласованным переведением трафика после проверки.

**Основание.** Идентификатор базового образа и версия на диске могут расходиться с фактическим хостом. Снимок позволяет восстановить исходный экземпляр с прежней ОС. Отдельная система позволяет проверить БД и данные до переключения, а также контролировать запись и откат. Поддерживаемый in-place путь потребовал бы перехода через 22.04 и нескольких окон простоя. Фактические ОС, flavor, среда запуска и доступ к Lightsail пока неизвестны. [AWS Linux](https://docs.aws.amazon.com/lightsail/latest/userguide/address-cve-2026-98432.html) [Canonical CVE](https://ubuntu.com/security/CVE-2026-98432) [Canonical LTS](https://ubuntu.com/about/release-cycle) [Lightsail snapshots](https://docs.aws.amazon.com/lightsail/latest/userguide/understanding-snapshots-in-amazon-lightsail.html) [Ubuntu upgrade](https://ubuntu.com/server/docs/how-to/software/upgrade-your-release/)

## Приоритеты аудита репозитория

**Решение.** Начать с PHP и npm lock-файлов, маршрутов V1 и legacy, доступа к данным, импорта, настройки образа, границ CI, а также примеров веб-сервера и сети. Зафиксировать доказательства для каждого вывода. Проверять хост только разрешёнными штатными средствами.

**Основание.** По коду URL протокола поступает из DTO в сетевое чтение без явно заданной политики допустимых назначений. Это кандидат на приоритетное исправление, совместимость требуется сверить с используемыми внешними источниками. Dockerfile копирует весь контекст, а часть production-локальных файлов исключена только из Git. Пример Compose публикует порты БД и Redis. Эти два факта не подтверждают, что чувствительные файлы попали в опубликованный образ или порты доступны извне.

**Альтернативы.** Повторить проверку CI недостаточно для оценки работающих сервисов. Активные атаки и воспроизведение CVE исключены из методики проверки.

## Vitest и инструменты SPA

**Решение.** Владелец согласовал Vitest 5.1.1+ после finding в dev-зависимостях. Ветка Vite 6 остаётся совместимой при версии 6.4+, минимальный Node.js повышается до 22.12. Сначала целевые совместимые обновления, затем миграция Vitest и полный frontend CI.

**Основание.** Production advisory в `source-map-js` устраняется точечным обновлением. Полный npm audit отдельно выявил Critical в цепочке Vitest 3 / tinypool. Автоматический принудительный update всех пакетов отклонён, чтобы сохранить контролируемую область изменений. [Миграция Vitest](https://vitest.dev/guide/migration/) [Релиз Vitest 5.1.1](https://github.com/vitest-dev/vitest/releases/tag/v5.1.1)
