# Проверка фичи 057

## Репозиторий и CI

В локальной среде с PHP 8.5, Node.js 22.12+ и изолированной тестовой БД установить зависимости из lock-файлов и выполнить проверки.

```sh
composer install --no-interaction
composer validate --strict
composer check-platform-reqs
composer audit --locked --no-dev --no-interaction
npm ci
npm audit --omit=dev
```

Затем прогнать `composer cs`, `composer stan`, `composer rector -- --dry-run`, `composer test` и `npm run ci`. Убедиться, что приложение стартует. Если аудит сообщает новые advisories, записать риски и разрешить их по приоритету. Ошибка доступа к реестру считается непройденной проверкой до успешного повтора.

## Lightsail

На исходном Ubuntu 20.04 запущено ядро `5.4.0-1018-aws`. Узнать, доступен ли исправленный `linux-aws` для действующего хоста, можно штатной инвентаризацией.

```sh
uname -r
pro status
apt-cache policy linux-aws linux-image-aws
apt-cache depends linux-image-aws
docker compose ps --status running --services
docker compose exec -T app php-fpm -v
```

APT показывает метапакет `5.15.0.1084.91~20.04.1`, который ведёт на более старую сборку 5.15 без нужного исправления. Для Ubuntu 20.04 Canonical указывает исправления начиная с `5.4.0-1169.180` в семействе `linux-aws` и `5.15.0-1120.127~20.04.1` в семействе `linux-aws-5.15`. Обе сборки доступны через Ubuntu Pro. Проверить `esm-infra` и обновить индексы APT. Если исправленная сборка доступна, после резервирования и согласования окна применить её и перезагрузиться. Если доступа к исправлению нет, ускорить выкат на подготовленный 24.04. [Canonical CVE](https://ubuntu.com/security/CVE-2026-98432) [Ubuntu Pro](https://documentation.ubuntu.com/pro-client/en/latest/howtoguides/enable_esm_infra/) [AWS](https://docs.aws.amazon.com/lightsail/latest/userguide/address-cve-2026-98432.html)

1. С разрешённой сессии проверить релиз ОС, загруженное ядро, способ запуска веб-сервиса, FPM, Horizon и scheduler. Для контейнеров записать образ и digest. Для нативных процессов определить путь к фактическому исполнимому файлу и пакет. Сравнить с [контрактом](contracts/security-verification.md).
2. Перед изменениями подготовить согласованное окно и проверенное восстановление. Для миграции проверить восстановление БД, загруженных файлов и нужной конфигурации на отдельной Ubuntu 24.04. Согласовать режим записи, финальную синхронизацию, IP/DNS и откат с учётом новых данных.
3. После установки исправлений перезапустить нужные процессы или перезагрузить хост, затем повторно подтвердить загруженные версии. При переносе сначала проверить новый экземпляр и только потом переключать трафик.
4. Проверить HTTPS, публичное чтение, вход, авторизованную загрузку тестового файла и обработку фоновой задачи на согласованном тестовом наборе. Привязать результаты к фактическому времени и версии релиза.

Версия CLI полезна для сравнения. Доказательство веб-рантайма берётся из актуального FPM или веб-модуля. Не публикуйте страницу с конфигурацией PHP. Проверки выполняются штатными запросами, без воспроизведения уязвимостей.

### Перенос с Ubuntu 20.04

1. Сохранить снимок Lightsail и отдельные согласованные резервные копии MySQL, протоколов, загруженных файлов и конфигурации. В Lightsail создать экземпляр в том же регионе через **Create instance → Linux/Unix → OS Only**, выбрав Ubuntu 24.04 LTS. Снимок возвращает систему с прежней ОС. При обновлении на месте путь проходит последовательно через Ubuntu 22.04. [Lightsail instances](https://docs.aws.amazon.com/lightsail/latest/userguide/getting-started-with-amazon-lightsail.html) [Lightsail snapshots](https://docs.aws.amazon.com/lightsail/latest/userguide/understanding-snapshots-in-amazon-lightsail.html) [Ubuntu upgrade](https://ubuntu.com/server/docs/how-to/software/upgrade-your-release/)
2. На новом экземпляре применить обновления ОС, проверить загруженное ядро, собрать образ приложения из проверенного релиза и восстановить копии. Сверить миграции, выборочные данные и открытие протоколов. Доступы, TLS, действующие ключи приложения и правила firewall передаются штатным закрытым способом.
3. Перед переключением остановить запись и фоновые процессы на прежней системе, перенести изменения с момента репетиции, затем переназначить существующий Lightsail Static IP в том же регионе или обновить DNS. При использовании IPv6 отдельно сверить запись AAAA. Включить единственный рабочий набор очередей и расписания. Выполнить smoke-проверки из US2. [Lightsail Static IP](https://docs.aws.amazon.com/lightsail/latest/userguide/lightsail-create-static-ip.html)
4. При необходимости отката сначала согласовать судьбу данных, записанных после переключения. Сохранить новую копию и восстановить сервис на проверенной версии с исправленным runtime. Зафиксировать фактический простой, потерю данных при наличии и результаты проверок.
