# Quickstart: валидация рефакторинга

**Feature**: 002-modernize-codebase | **Date**: 2026-08-26

Руководство по проверке, что обе части выполнены корректно и поведение не изменилось. Решения — в
[research.md](./research.md), список шагов — в plan.md / будущем tasks.md.

## Предпосылки

- Ветка `002-modernize-codebase` (создана от `001-upgrade-stack`; стек уже на PHP 8.5 / Laravel 13).
- Активен PHP 8.5 (`php -v` → 8.5.x; при необходимости `export PATH="/opt/homebrew/bin:$PATH"`).
- Рабочее дерево чистое; каждый шаг — отдельная правка/коммит.

## Базовая линия (до рефакторинга)

Зафиксировать «зелёное до»:

```bash
composer test          # ~237 тестов зелёные
composer stan          # PHPStan/Larastan lvl 5 — без ошибок
composer cs            # php-cs-fixer — без нарушений
composer rector -- --dry-run   # чисто (нет предлагаемых изменений)
```

## Гейты после КАЖДОГО шага (Definition of Done шага)

```bash
composer test
composer stan
composer cs
composer rector -- --dry-run     # просмотреть diff; при необходимости composer rector
php artisan serve                # smoke: приложение стартует
git commit -m "refactor: <что именно>"   # отдельный изолированный коммит
```

## Проверки, специфичные для частей

### Часть 1 — переименование слоя (US1)

- Каталог переименован: `test -d app/Infrastructure && ! test -d app/Infrastracture`.
- Namespace обновлён во всех классах слоя: `grep -rl "namespace App\\\\Infrastructure" app/Infrastructure | wc -l` = 16.
- Ноль остатков опечатки в исполняемом коде/тестах/конфигах (исторические спеки исключены):
  `grep -rn "Infrastracture" app tests config database bootstrap` → пусто.
- Автозагрузка работает: `composer dump-autoload` без ошибок; приложение бутается (`php artisan --version`).
- DI-биндинги резолвятся: провайдеры в `app/Bridge/Laravel/Provider/*` ссылаются на `App\Infrastructure\...`;
  request/feature-тесты, дергающие эти биндинги, зелёные.
- Все ранее зелёные тесты остаются зелёными; поведение идентично.

### Часть 2 — модернизация как стандарт (US2, объём — максимум, область `app/`+`tests/`)

- `->withPhpSets()` + строгие prepared-sets (`strictBooleans`/`naming`/`instanceOf`; при пользе —
  уровневые `withTypeCoverageLevel` и т.п.) включены в `rector.php`; `composer rector` применяет
  максимальный набор модернизаций PHP 8.5 к `app/` и `tests/`.
- Дифф — только форма (короче/единообразнее/строже типы), не поведение; подтверждается зелёными тестами.
- Небезопасные/шумные правила исключены через `withSkip`, изменения откачены (агрессивно пробуем —
  гейты отбраковывают).
- **Идемпотентность**: повторный `composer rector -- --dry-run` → «Rector is done!» без изменений (SC-004).
- Согласованность со стилем: `composer cs` зелёный (правило импорт-вместо-FQCN не нарушено).
- **Закрепление стандарта проверяется практически**: внести в код заведомо устаревшую конструкцию,
  прогнать `composer rector -- --dry-run` / `composer cs` — инструмент предлагает привести к современному
  виду (SC-005); тестовую правку откатить.

## Критерий приёмки фичи (из spec.md)

- SC-001: ноль вхождений `Infrastracture` в исполняемом коде/тестах/конфигах после Части 1.
- SC-002: 100% ранее проходивших тестов остаются зелёными; поведение не изменилось.
- SC-003: каждый шаг — отдельный откатываемый коммит с зелёными гейтами.
- SC-004: правила модернизации закреплены в конфиге и идемпотентны (повторный прогон — ноль изменений).
- SC-005: устаревшая конструкция после закрепления стандарта отмечается/автоприводится инструментом.
- SC-006: Часть 1 выполнена и проверена независимо от Части 2.
