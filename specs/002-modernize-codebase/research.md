# Research: Модернизация кодовой базы и исправление опечатки слоя

**Date**: 2026-08-26 | **Feature**: 002-modernize-codebase

Разведка по двум частям фичи: (1) безопасное переименование слоя `Infrastracture` → `Infrastructure`,
(2) применение и закрепление современных конструкций PHP 8.5 / Laravel 13. Все факты сверены с
установленными инструментами и текущим состоянием репозитория (после фичи 001: PHP 8.5, Laravel 13.26.1).

---

## Состояние на входе (факты репозитория)

- Слой: каталог `app/Infrastracture`, namespace `App\Infrastracture` — **16 классов**, ~**38 файлов**
  со ссылками (`use`, `::class`, DI-биндинги в `app/Bridge/Laravel/Provider/*`, реализации интерфейсов
  из `app/Domain/*`, тесты).
- PSR-4 в `composer.json` — общий маппинг `App\ → app/`; **отдельного маппинга `Infrastracture` нет**,
  поэтому composer.json править не нужно — достаточно переименовать каталог и namespace.
- Инструменты качества настроены: `rector.php` (сеты `UP_TO_LARAVEL_130`, PHPUnit + prepared-sets
  `deadCode/codeQuality/typeDeclarations/privatization/earlyReturn`, `withImportNames`), `.php-cs-fixer.php`
  (в т.ч. `global_namespace_import`, `fully_qualified_strict_types`, 6 modernize/migration-правил),
  PHPStan/Larastan (lvl 5), ~237 тестов. `composer.json` floor `php ^8.5`.
- Rector поддерживает `LevelSetList::UP_TO_PHP_85` и метод `->withPhpSets()`. **Явного PHP-сета в
  `rector.php` сейчас НЕТ** — это главное недостающее звено для US2.
- PhpStorm открыт с проектом `bfo-base` → доступен семантический `ide_refactor_rename` (альтернатива).

---

## Decision 1 — Порядок: сначала US1 (rename), затем US2 (modernize)

- **Decision**: Выполнить Часть 1 (переименование слоя) первой и отдельными коммитами, затем Часть 2
  (модернизация).
- **Rationale**: US1 — точечное, детерминированное, срочное (видимый дефект), независимое (P1). Если
  сделать модернизацию первой, её широкий дифф смешается с переименованием и усложнит ревью/откат.
  US1 закрывается и мержится сам по себе (FR-013/SC-006).
- **Alternatives**: US2 первым — отвергнуто (широкий дифф поверх опечатки, конфликт diff-ов).

## Decision 2 — US1: детерминированная замена namespace + `git mv`, гейты как страховка

- **Decision**: Переименовать слой так:
  1. `git mv app/Infrastracture app/Infrastructure` (сохраняет историю, переносит структуру);
  2. заменить строку `App\Infrastracture` → `App\Infrastructure` во всех `.php` (namespace-объявления,
     `use`, `::class`, DI-биндинги, тесты) — цель `Infrastracture` встречается только внутри имени слоя,
     ложных совпадений нет;
  3. `composer dump-autoload` (перегенерировать PSR-4 карту);
  4. прогнать гейты + приложение; `grep -r Infrastracture` по коду/тестам/конфигам = 0.
- **Rationale**: Строка `Infrastracture` уникальна (это и есть опечатка), поэтому текстовая замена
  безопасна и детерминирована. PHPStan (ненайденные классы), автозагрузка и 237 тестов — надёжная
  страховка от промаха. Не зависит от IDE-сессии, воспроизводимо в CI/на другой машине.
- **Alternatives**:
  - **PhpStorm `ide_refactor_rename`** (проект открыт) — семантически надёжно, но MCP-инструмент
    работает по одному символу/файлу; переименование namespace-сегмента для 16 классов через него
    громоздко и завязано на живую IDE-сессию. Оставляем как страховочный вариант, если текстовая
    замена что-то упустит.
  - **Rector `RenameClassRector`** на 16 классов — избыточно многословный конфиг ради разовой операции.

## Decision 3 — US2: максимальный набор в rector.php как разовый проход И постоянный стандарт

> **Уточнено 2026-08-26 (clarify):** объём US2 — **максимальный** (полный PHP 8.5 + строгие наборы),
> область — `app/` **и** `tests/`.

- **Decision**: В `rector.php` включить максимальный набор модернизаций:
  1. `->withPhpSets()` — берёт целевую версию PHP из `composer.json` (`^8.5`) и применяет полный
     PHP-версионный сет (self-syncing со стеком);
  2. усилить `->withPreparedSets(...)` строгими группами (напр. `strictBooleans: true`, `naming: true`,
     `instanceOf: true`) сверх уже включённых `deadCode/codeQuality/typeDeclarations/privatization/earlyReturn`;
  3. рассмотреть уровневые наборы (`withTypeCoverageLevel`/`withDeadCodeLevel`/`withCodeQualityLevel`) для
     повышения строгости типов, если дают полезный дифф без ломки поведения;
  4. в `.php-cs-fixer.php` — `declare_strict_types` уже включён; при необходимости усилить стилевые
     migration-правила.
  Пути rector уже включают `app`, `bootstrap`, `config`, `public`, `resources`, `tests` — область `app/`
  и `tests/` покрыта из коробки. Это одновременно (а) разовый проход по базе (US2 «применить») и
  (б) закрепление стандарта — rector/cs-гейт впредь приводит новый код к тем же конструкциям (FR-007).
- **Rationale**: владелец выбрал максимальную строгость («только вперёд», принцип V). prepared-sets
  качества и Laravel-сет уже работают; недостают PHP-версионный сет и строгие группы. `withPhpSets()`
  без аргументов синхронизируется с composer floor — версию не хардкодим.
- **Точный список строгих наборов финализируется на implement**: включаем по одной группе, смотрим дифф
  и гейты; группа/правило, меняющее наблюдаемое поведение (ловится тестами/stan) или дающее шум, —
  исключается через `withSkip` (как в 001 для `RenameMethodRector` на `ViewProvider`), изменение
  откатывается (FR-008). Это делает «максимум» безопасным: агрессивно пробуем, гейты отбраковывают.
- **Alternatives**:
  - Консервативное подмножество — отвергнуто владельцем (нужен максимум).
  - Явный `LevelSetList::UP_TO_PHP_85` вместо `withPhpSets()` — эквивалентно, но версию пришлось бы
    обновлять вручную; `withPhpSets()` предпочтительнее (self-syncing).
  - Разовый прогон без закрепления в конфиге — отвергнуто: противоречит FR-007.

## Decision 4 — php-cs-fixer: закрепить migration-стиль по необходимости

- **Decision**: Основную модернизацию несёт rector. php-cs-fixer уже содержит modernize-правила; при
  наличии стабильного migration-ruleset под целевой PHP — добавить его для стилевой части (напр. приведение
  синтаксиса). Если ruleset под 8.5 в установленной версии отсутствует/нестабилен — не форсировать,
  rector покрывает.
- **Rationale**: Разделение ответственности: rector — семантические модернизации, cs-fixer — стиль.
  Дублирование правил чревато конфликтом; согласуем так, чтобы повторный прогон был идемпотентным (FR-009).
- **Alternatives**: Перенести всё в cs-fixer — отвергнуто (rector мощнее для модернизаций синтаксиса/типов).

## Decision 5 — Идемпотентность и разбивка диффа

- **Decision**: Критерий готовности US2 — повторный `composer rector --dry-run` даёт ноль изменений, а
  `cs`/`stan`/`test` зелёные (SC-004). Если дифф модернизации слишком большой для одного ревью — разбить
  на осмысленные коммиты по группам правил (напр. отдельный коммит на PHP-сет, отдельный — на дочистку
  стиля).
- **Rationale**: Обозримость и откатываемость (FR-012). Идемпотентность гарантирует, что стандарт
  действительно «устоялся», а не оставляет хвост.

## Итоговый порядок шагов (для tasks)

1. **US1 — переименование слоя** (P1, независимо):
   `git mv` каталога → замена namespace/ссылок → `dump-autoload` → гейты → `grep Infrastracture` = 0 → коммит.
2. **US2 — модернизация как стандарт** (P2, после US1, объём — максимум, область `app/`+`tests/`):
   поэтапно включать группы правил в `rector.php` (`withPhpSets()` → строгие prepared-sets
   `strictBooleans/naming/instanceOf` → при пользе уровневые `withTypeCoverageLevel` и т.п.); после
   каждой группы `composer rector` → просмотр диффа (только форма) → небезопасное через `withSkip` +
   откат → гейты → отдельный коммит. Финал: идемпотентность (`--dry-run` чист) + при необходимости
   усиление `.php-cs-fixer.php`.
