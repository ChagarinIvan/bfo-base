# Implementation Plan: Модернизация кодовой базы и исправление опечатки слоя

**Branch**: `002-modernize-codebase` | **Date**: 2026-08-26 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/002-modernize-codebase/spec.md`

## Summary

Чистый рефакторинг без изменения поведения, две части. **Часть 1 (US1, P1)**: исправить опечатку в
имени слоя — переименовать `app/Infrastracture` → `app/Infrastructure` и namespace `App\Infrastracture`
→ `App\Infrastructure` во всех классах и ссылках (`git mv` + детерминированная текстовая замена +
`dump-autoload`), гейты как страховка. **Часть 2 (US2, P2)**: применить **максимальный** набор
современных конструкций PHP 8.5 (полный PHP-сет + строгие наборы, напр. strict-booleans/strict-types) и
идиом Laravel 13 к `app/` **и** `tests/`, закрепив как постоянный стандарт в `rector.php`/`.php-cs-fixer.php`.
Каждый логический шаг — отдельный коммит с зелёными гейтами (`test`/`stan`/`cs`/`rector`). Порядок:
US1 → US2 (см. [research.md](./research.md)).

## Technical Context

**Language/Version**: PHP 8.5 (composer floor `^8.5`).

**Primary Dependencies**: Laravel 13.26.1; инструменты качества — Rector (`driftingly/rector-laravel`
`UP_TO_LARAVEL_130`, prepared-sets + `withImportNames`; добавляются `withPhpSets()` и строгие наборы),
php-cs-fixer 3.95 (`global_namespace_import`, `fully_qualified_strict_types`, `declare_strict_types`),
PHPStan/Larastan lvl 5.

**Storage**: MySQL через Eloquent — не затрагивается (рефакторинг формы кода, не схемы/данных).

**Testing**: PHPUnit 13.x, ~237 тестов (регресс-сеть). Гейты: `composer test`/`stan`/`cs`/`rector`.
Гейты прогоняются на активном PHP 8.5.

**Target Platform**: Docker (php:8.5-fpm) на проде; локально — PHP 8.5 на маке + `php artisan serve`.

**Project Type**: Web-приложение (Laravel-монолит, слои DDD + Bridge; фронт Blade в миграции на SPA).

**Performance Goals**: N/A — рефакторинг не меняет поведение/производительность.

**Constraints**: Ноль изменений наблюдаемого поведения (FR-011); каждый шаг — отдельный откатываемый
коммит с зелёными гейтами (FR-012); US1 независим от US2 (FR-013); правила модернизации идемпотентны
(FR-009) и согласованы с правилом кодстайла (принцип VI). Строгие наборы применяются агрессивно;
небезопасное правило отсеивается гейтами и исключается через `withSkip` (FR-008).

**Scale/Scope**: US1 — 16 классов + ~38 файлов ссылок. US2 — **широкий** дифф по `app/` и `tests/`
(максимальный набор + строгие правила), разбивается на обозримые коммиты по группам правил.

### Source Code (repository root)

Фича затрагивает имя слоя инфраструктуры и конфигурацию инструментов качества. Реальные пути:

```text
app/Infrastracture/      → app/Infrastructure/     # US1: переименование каталога (16 классов)
app/                     # US1: обновление ссылок (Bridge-провайдеры, Domain-интерфейсы); US2: модернизация формы
tests/                   # US1: ссылки в тестах; US2: модернизация формы (входит в объём — уточнение 2026-08-26)
config/                  # US1: возможные ссылки на namespace слоя (DI/конфиг)
rector.php               # US2: ->withPhpSets() + строгие prepared-sets (закрепление стандарта)
.php-cs-fixer.php         # US2: при необходимости — усиление стилевых/migration-правил
composer.json            # US1: правки НЕ требуются (PSR-4 общий App\ → app/)
```

**Structure Decision**: новых каталогов/структур не создаётся. US1 — переименование существующего слоя
и его ссылок. US2 — точечные правки конфигов инструментов + широкий механический дифф по `app/` и
`tests/`. Каждый шаг — минимальный/обозримый набор файлов, отдельный коммит.
