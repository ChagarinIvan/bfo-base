# Event processing status contract

Authenticated event list and detail responses include the Event's current `processingStatus`: `parsing`, `identifying`, `rebuildingRanks`, `ready`, `parsingError`, `identifyingError`, or `rebuildingRanksError`. They also include nullable `errorMessage`, containing only text safe to show to users. A new protocol clears it. Every Event has a non-null processing status and token. Public list/detail responses include only events whose status is `ready`; they do not expose `errorMessage`. Public distance requests require a ready Event, and public protocol-line lists include only lines belonging to a ready Event.

The SPA polls the event detail and currently visible list page every five seconds while at least one visible event has a transitional status (`parsing`, `identifying`, or `rebuildingRanks`). Polling stops after `ready`, any of the three error statuses, route change, or unmount. The authenticated UI displays a stage-specific status label and `errorMessage`, falling back to a localized stage-specific message if it is null. Creating an Event with a protocol returns `parsing` immediately; there is no queued/null interval while a separate run is created. A partial identification remains `identifying`; the internal processing token and per-line progress are not exposed in this API.
