# Quickstart: валидация шагов апгрейда

**Feature**: 001-upgrade-stack | **Date**: 2026-08-19

Этот документ — руководство по проверке, что каждый шаг апгрейда выполнен корректно и поведение не
изменилось. Детали решений — в [research.md](./research.md), список шагов — в plan.md / будущем tasks.md.

## Предпосылки

- Docker-окружение поднято локально, БД MySQL доступна.
- Установлено расширение **phpredis** в PHP-контейнере (и на воркерах) — проверка:
  `php -m | grep redis`.
- Рабочее дерево чистое; текущий шаг делается в отдельной ветке/коммите.

## Базовая линия (до первого шага)

Зафиксировать «зелёное до»:

```bash
composer install
composer test          # PHPUnit — все ~115 тестов зелёные
composer stan          # PHPStan/Larastan lvl 5 — без ошибок
composer cs            # php-cs-fixer — без нарушений
php artisan serve      # приложение поднимается локально
```

Если какой-то гейт красный **до** апгрейда — сначала чиним базу, только потом апгрейд.

## Гейты после КАЖДОГО шага (Definition of Done шага)

Один и тот же ритуал повторяется после каждого шага; переход к следующему — только когда всё зелёное:

```bash
composer update <только-целевой-пакет>   # или правка Dockerfile/compose для инфра-шага
composer test
composer stan
composer cs
composer rector --dry-run                # просмотреть diff; при необходимости composer rector
php artisan serve                        # smoke: приложение стартует, ключевые страницы отвечают
git commit -m "upgrade: <что именно>"    # отдельный изолированный коммит
```

## Проверки, специфичные для шагов

- **Безопасные semver + rector-laravel**: `composer show driftingly/rector-laravel` присутствует;
  `composer update` не сообщает abandoned по rector-части; `composer rector --dry-run` работает.
- **Удаление doctrine/dbal**: пакета нет в `composer.lock`; мёртвый `use Doctrine\DBAL\Types\Type;` удалён;
  `php artisan migrate --pretend` на свежей БД проходит (миграции с `->change()` не требуют dbal в Laravel 11+).
- **Удаление predis / phpredis**: `php -m | grep redis` (расширение есть); кэш и очереди работают —
  прогнать тесты + вручную проверить сценарий с кэшем и постановкой job в Horizon.
- **phpspreadsheet 5.x**: зелёные **18 parser-тестов** (`tests/Models/Parser/*`); вручную импортировать
  реальный `.xlsx` и `.xls` протокол — данные распарсились идентично прежнему.
- **Laravel 11→12**: проверить использование `HasUuids` (UUIDv7 vs `HasVersion4Uuids`), Carbon-3 поведение
  дат, загрузку изображений (SVG больше не проходит `image`), пути `local`-диска. Rector `UP_TO_LARAVEL_120`.
- **Laravel 12→13**: CSRF — старое имя `VerifyCsrfToken` алиасится, но проверить кастомные ссылки;
  `serializable_classes` (кэш объектов) и сериализация сессий (`json`) — активные сессии инвалидируются;
  `upsert` с пустым `uniqueBy`. Rector `LaravelSetList::LARAVEL_130`.
- **PHP 8.4→8.5**: `docker compose exec app php -v` → 8.5; `php -m` — все нужные расширения на месте;
  прогнать полный тест-сьют; проверить предупреждения по PDO-константам / кастам.
- **Инфра-образы**: перед MySQL — `mysqldump` бэкап; после пересоздания контейнеров данные на месте,
  приложение отвечает, теги в compose зафиксированы (не `latest`).

## Критерий приёмки фичи (из spec.md)

- SC-001: 100% шагов завершены с зелёными гейтами.
- SC-002: ноль изменений поведения (ранее зелёные тесты остаются зелёными; ключевые сценарии идентичны).
- SC-003: каждый шаг — отдельный откатываемый коммит.
- SC-004: ноль abandoned-зависимостей; ноль образов на `latest`.
- SC-005: весь стек на целевых версиях (PHP 8.5, Laravel 13.x, …).
- SC-006: данные БД сохранены после инфра-апгрейда.
