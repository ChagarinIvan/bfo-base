# Исследование: ручная активация I разряда

## Единое правило

**Решение**: исключить `FirstRank` из `Rank::isAutomaticallyActivated()`. `StandardProtocolParser` использует метод для нового `ProtocolLineInput`, а `RankCalculator` использует его как запасное правило для строк без даты. Одно изменение охватывает создание и пересчёт.

**Альтернатива**: изменить только парсер. Отклонена, поскольку калькулятор снова активирует новую строку с пустой датой.

## Сохранение прежних активаций

**Решение**: оставить исторические строки без изменения. Прежний парсер уже записывал дату автоматической активации I разряда в `protocol_lines.activate_rank`. Калькулятор берёт эту дату при пересчёте, даже когда I разряд больше не считается автоматически активируемым.

**Альтернатива**: миграцией копировать дату из истории в строку протокола. Отклонена после проверки старого пути записи: дата уже находится в строке, поэтому перенос не нужен.

## Другие разряды и повторные достижения

SQL в `EloquentProtocolLineOperations::activateEventLines()` включает только КМС и МС и не меняется. Повторный I разряд остаётся ожидающим ручной активации. II, III и юношеские категории сохраняют автоматическую активацию. API истории и активации не ограничивают действие КМС и МС, поэтому новый endpoint не требуется.
