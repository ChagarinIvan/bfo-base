# Чеклист качества требований: управление группами в SPA

## Полнота

- [ ] Описаны публичный список групп и страница группы.
- [ ] Зафиксированы pagination, поиск от одного символа и debounce.
- [ ] Зафиксированы поля `ViewGroupDto` и auth-only `created`/`updated`.
- [ ] Описаны фильтры списка стартов и отсутствие действий в его таблице.
- [ ] Описаны edit, duplicate prevention, delete popup и merge workflow.
- [ ] Описаны redirect-совместимость и удаление legacy после аудита usages.

## Проверяемость

- [ ] Для каждой пользовательской истории есть независимый тест и acceptance scenarios.
- [ ] Сортировка и стабильность пагинации заданы измеримо.
- [ ] Указаны HTTP-контракты для validation, auth и duplicate conflict.
- [ ] Зафиксированы критерии отсутствия N+1 и правило обоснования индекса.

## Согласованность

- [ ] Термины `Group`, `ViewGroupDto`, `Event/Start`, source/target используются единообразно.
- [ ] Требование к существующему `events` API отражает `groupId` и `withCompetition`.
- [ ] Legacy shared dependencies отделены от group-only web-кода.
- [ ] Scope не включает создание групп, undo merge и редактирование стартов.

## Готовность к планированию

- [ ] Нет маркеров `NEEDS CLARIFICATION`.
- [ ] Архитектурные слои и тестовые ограничения указаны.
- [ ] Все обязательные разделы спецификации заполнены.
