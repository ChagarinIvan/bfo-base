# Спецификация фичи: таблица кубка в SPA

**Ветка фичи**: `037-cup-table-spa`  
**Создано**: 2026-09-23  
**Статус**: Draft

## Входная проблема

Старая таблица кубка доступна по адресу `/cups/{cupId}/{groupId}/table` и
рендерится Blade-шаблоном. Страница показывает карточку кубка, этапы и итоговую
таблицу выбранной возрастной группы. В SPA уже есть карточка кубка и список этапов,
но полноценная таблица кубка отсутствует. Переход между этапами и таблицей должен
происходить внутри одной страницы без полной перезагрузки.

## Пользовательские сценарии и тестирование

### История 1 — просмотр кубка и переключение содержимого (P1)

Пользователь открывает страницу кубка и видит карточку сверху. Под карточкой он
переключает вкладки «Этапы» и «Таблица», как вкладки в `PersonView`.

**Сценарии приемки**:

1. **Дано** существующий кубок, **когда** открыт `/app/cups/{cupId}`, **тогда**
   сверху отображается карточка кубка, а снизу список этапов.
2. **Дано** карточка кубка, **когда** пользователь выбирает «Таблица», **тогда**
   верхняя карточка сохраняется, нижняя часть меняется без полной перезагрузки.
3. **Дано** прямой URL таблицы с группой, **когда** он открыт или обновлён,
   **тогда** карточка и таблица восстанавливаются для этой группы.
4. **Дано** несколько групп кубка, **когда** пользователь выбирает вкладку группы,
   **тогда** таблица меняется без перезагрузки, а выбранная группа обозначена
   активной.

### История 2 — просмотр итоговой таблицы группы (P1)

Пользователь просматривает участников выбранной группы и очки по каждому этапу,
итог, среднее и место.

**Сценарии приемки**:

1. **Дано** выбранная группа, **когда** таблица загружена, **тогда** отображаются
   номер места, спортсмен, год рождения, клуб, отдельная колонка каждого этапа,
   сумма очков, среднее и итоговое место.
2. **Дано** этап с результатом участника, **когда** пользователь нажимает его
   очки, **тогда** открывается соответствующая строка протокола этапа.
3. **Дано** зачётные и незачётные этапы по правилам типа кубка, **когда** таблица
   построена, **тогда** зачётные очки выделены так же, как в старом Blade-шаблоне,
   а сумма и среднее используют только зачётные этапы.
4. **Дано** участник без результата на этапе, **когда** строка отображается,
   **тогда** ячейка этапа остаётся пустой или показывает установленный для этого
   случая прочерк и не создаёт ложных очков.

### История 3 — выбор группы, поиск, пагинация и настройка колонок (P1)

Пользователь выбирает группу, быстро находит спортсмена и управляет шириной
таблицы. Поведение фильтра имени повторяет `ListCupEventPointsService`.

**Сценарии приемки**:

1. **Дано** кубок с группами, **когда** открыта таблица, **тогда** отображается
   обязательный селект группы с группами этого кубка и выбранной группой.
2. **Дано** фильтр имени, **когда** введено менее трёх символов, **тогда** запрос
   не отправляется и показывается подсказка о минимальной длине.
3. **Дано** минимум три символа, **когда** ввод стабилизировался, **тогда** таблица
   загружается с выбранным `groupId` и фильтром имени и возвращается на первую
   страницу.
4. **Дано** больше одной страницы, **когда** пользователь меняет страницу,
   **тогда** загружается соответствующий срез без потери выбранной группы и
   фильтра.
5. **Дано** список колонок, **когда** пользователь скрывает необязательную
   колонку, **тогда** она исчезает и настройка сохраняется для этой таблицы.
6. **Дано** колонка этапа, **когда** пользователь открывает настройки колонок,
   **тогда** её нельзя скрыть. Все колонки этапов остаются видимыми.

### История 4 — ошибки и совместимость (P2)

Пользователь получает понятное состояние при ошибке, а старые URL продолжают
открывать старую страницу до завершения миграции.

**Сценарии приемки**:

1. **Дано** ошибка загрузки таблицы, **когда** API отвечает ошибкой, **тогда**
   верхняя карточка сохраняется, нижняя часть показывает сообщение с возможностью
   повторить загрузку.
2. **Дано** несуществующий кубок или группа, **когда** открыт SPA URL, **тогда**
   отображается стандартная страница 404.
3. **Дано** старый URL `/cups/{cupId}/{groupId}/table`, **когда** он открыт,
   **тогда** существующая совместимость маршрута не ломается, пока legacy route
   не будет выведен отдельно.

## Граничные случаи

- У кубка нет этапов или групп: карточка отображается, нижняя часть показывает
  пустое состояние.
- У кубка один этап: сохраняется отдельная колонка этапа и итоговые колонки.
- Длинное имя клуба или спортсмена не ломает горизонтальную прокрутку таблицы.
- Пагинация сохраняет группу, поиск и выбранные колонки.
- Быстрое переключение групп не должно позволить старому ответу заменить новую
  таблицу; отмена или идентификация устаревших запросов обязательна.
- Гостю доступны публичные данные таблицы; административные действия остаются
  только для авторизованных пользователей.

## Функциональные требования

- **FR-001**: SPA MUST показывать карточку кубка и нижнюю область с вкладками
  «Этапы» и «Таблица».
- **FR-002**: переключение вкладок и групп MUST менять только нижнюю область без
  полной перезагрузки документа.
- **FR-003**: таблица MUST отображать фиксированный порядок: место, спортсмен,
  год рождения, клуб, все этапы по датам, сумма, среднее, место.
- **FR-004**: каждая колонка этапа MUST иметь ссылку на просмотр этапа и MUST быть
  обязательной для отображения.
- **FR-005**: остальные колонки MUST поддерживать скрытие и восстановление
  настройки через существующий механизм таблиц.
- **FR-006**: таблица MUST иметь обязательный селект `groupId` из групп текущего
  кубка и поддерживать серверную пагинацию и фильтр по имени; фильтр применяется
  только от трёх символов.
- **FR-007**: backend MUST предоставить read-only V1 контракт для пагинированной
  таблицы группы с этапами, очками, итогом, средним, местом и ссылочными ID.
- **FR-008**: расчёт зачётных очков, суммы, среднего и места MUST совпадать с
  текущим `CupEventsService::calculateCup()` и старым Blade-представлением.
- **FR-009**: API MUST возвращать метаданные этапов в стабильном порядке и данные
  строк, достаточные для ссылок на протокол и клуб/спортсмена.
- **FR-010**: ошибки, пустые результаты, 404, невалидную/отсутствующую группу и
  устаревшие ответы MUST иметь
  отдельные проверяемые состояния в SPA.
- **FR-011**: изменённые V1 actions и API-контракты MUST иметь request-тесты с
  camelCase query-параметрами и `@see` на action.

## Ключевые сущности

- **Кубок**: карточка, год, тип и список доступных групп.
- **Группа кубка**: выбранная категория, например `M_0_`/`M21`, для которой
  строится таблица.
- **Этап**: событие кубка с датой, ID просмотра этапа и максимальными очками.
- **Строка таблицы**: спортсмен, клуб, год рождения, очки по каждому этапу, сумма,
  среднее и место.
- **Ячейка этапа**: очки и ссылка на protocol line, с признаком зачётности.

## Критерии успеха

- **SC-001**: пользователь открывает карточку и переключает «Этапы/Таблица» без
  полной перезагрузки.
- **SC-002**: таблица показывает все этапы выбранной группы в исходном порядке и
  совпадает с legacy расчётом по сумме, среднему и месту.
- **SC-003**: поиск от трёх символов и пагинация возвращают корректный срез без
  сброса группы и состояния вкладки.
- **SC-004**: 100% колонок этапов остаются видимыми после любых настроек колонок.
- **SC-005**: успешный и ошибочный сценарии, смена группы и устаревший ответ
  покрыты frontend/API тестами.

## Допущения и границы

- По умолчанию открывается вкладка «Этапы»; таблица доступна через вкладку и
  deep-link с выбранной группой.
- Для новой таблицы используется V1 API; legacy Blade и экспорт не удаляются.
- В первой версии не добавляются сортировки, отличные от порядка места/очков,
  и не меняются правила расчёта конкретных типов кубков.
