# Модель данных: Единая нормализация названий клубов

## Сущности и значения

| Элемент | Поля/значение | Правила |
|---|---|---|
| Club | name, normalize_name, active | name остаётся отображаемым именем; normalize_name — сопоставимый ключ для duplicate rule и поиска активного клуба. |
| ClubNameNormalizer | исходная строка → сопоставимое имя | Обрезает внешние пробелы, приводит к нижнему регистру, удаляет кавычки, схлопывает пробелы, приводит аналоги символов и известные варианты названий. |
| ProtocolLine | club | Новые parser results содержат значение без внешних пробелов; историческое значение не переписывается. |

## Инварианты

1. Одинаково нормализованные названия не могут принадлежать двум активным клубам
   при создании или обновлении.
2. Поиск по сопоставимому имени возвращает только активный клуб либо отсутствие
   совпадения.
3. Внешние пробелы не влияют на сопоставление названия с клубом.
4. Все преобразования названия выполняются одним ClubNameNormalizer; repository
   получает уже нормализованное значение.

## Переходы и потоки

~~~text
Создание/обновление клуба:
name → ClubNameNormalizer → normalize_name → duplicate check → Club

Импорт / идентификация:
внешнее название → ClubNameNormalizer → ClubRepository lookup → person.club_id

Разбор протокола:
format parser → ParserService trim(club) → ProtocolLine / идентификация

Legacy-рендер:
ProtocolLine.club и Club.name → ClubNameNormalizer → сопоставление ссылки
~~~

## Совместимость данных

- Структура таблиц и публичные DTO не меняются.
- Исторические protocol_lines не обновляются массово.
- Старые значения с внешними пробелами находят клуб благодаря trim в
  ClubNameNormalizer.
