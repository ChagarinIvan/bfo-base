# Источник данных и кэш

До исправления `StandardCupTableBuilder` использовал имя и год первого результата спортсмена. Запросы `ProtocolLinesRepository`, которые поставляют строки для расчёта, уже загружают `person` или `person.club`. Повторный запрос карточек не нужен.

`ViewCupTableService` ищет по готовому `personName`. `ExportCupTableService` использует тот же построитель, поэтому фильтр и экспорт получат исправленные данные через общую строку таблицы.

Тег `cups` объединяет варианты кэша таблиц. Новая версия ключей исключает чтение старых строк при выпуске, а существующая очистка тега обслуживает дальнейшие правки карточек.

Таблица отдельного этапа использует `CupAssembler` и получает готовые строки напрямую из расчёта этапа. Связь спортсмена уже загружена теми же запросами протоколов. Результат этого сценария не кэшируется.
