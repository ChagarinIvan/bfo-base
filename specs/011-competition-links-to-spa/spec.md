# Спецификация фичи: Перевод соревнований на SPA

**Ветка фичи**: `011-competition-links-to-spa`  
**Создано**: 2026-09-03  
**Статус**: Draft

**Входные данные**: Переключить все ссылки на листинг соревнований, просмотр, создание и
редактирование со старых Blade-страниц на существующие SPA-маршруты; удалить старые страницы
`ShowCompetitions...` и связанный legacy по возможности.

## Контекст и границы

SPA-страницы соревнований уже существуют по адресам `/app/competitions`,
`/app/competitions/{id}`, `/app/competitions/create` и `/app/competitions/{id}/edit`.
Сейчас часть navbar, redirect-ов, Blade-шаблонов и действий всё ещё ссылается на `/competitions`
и рендерит старые views. Нужно сделать SPA единственным пользовательским интерфейсом для
листинга, просмотра, создания и редактирования соревнований.

Удаление legacy ограничено только теми контроллерами, views, web routes, тестами и ссылками,
чья функция полностью покрывается SPA и V1 API. Операции этапов, протоколов, удаления и другие
неперенесённые разделы не удаляются молча; их ссылки должны остаться рабочими.

## Пользовательские сценарии и тестирование

### История 1 — Единая навигация соревнований (P1)

Посетитель из navbar, корневой страницы, страницы ошибки или после входа попадает в SPA-listing,
а не в Blade-listing.

**Независимая проверка**: проверить ссылки и redirect-ы без авторизации и после авторизации;
каждый вход в соревнования должен вести на `/app/competitions` с сохранением нужного года как
query-параметра, если он поддерживается SPA.

1. **Дано** пользователь нажал пункт соревнований в navbar, **когда** переход завершён,
   **тогда** открыт `/app/competitions`.
2. **Дано** пользователь открыл `/`, 404 или завершил login/registration flow, **когда**
   система возвращает его к соревнованиям, **тогда** используется SPA URL.
3. **Дано** в коде есть ссылка на листинг соревнований, **когда** выполняется инвентаризация,
   **тогда** рабочие ссылки не ведут на legacy `/competitions`.

### История 2 — SPA просмотр и управление (P1)

Пользователь открывает соревнование, создаёт новое или редактирует существующее через SPA без
Blade-форм и полной перезагрузки.

**Независимая проверка**: пройти список → просмотр → edit/create в браузере, а для защищённых
маршрутов проверить redirect неавторизованного пользователя в SPA login.

1. **Дано** пользователь нажал название соревнования, **тогда** открыт
   `/app/competitions/{id}`, а не `/competitions/{id}/show`.
2. **Дано** аутентифицированный пользователь выбирает создание, **тогда** открыт
   `/app/competitions/create` и используется V1 API.
3. **Дано** аутентифицированный пользователь выбирает редактирование, **тогда** открыт
   `/app/competitions/{id}/edit` с текущими данными.
4. **Дано** пользователь не авторизован, **когда** он открывает create/edit, **тогда** SPA
   перенаправляет на `/app/login`, не возвращая Blade-форму.

### История 3 — Удаление покрытого legacy (P2)

После переноса ссылок разработчик не находит старые competition list/show/create/edit pages,
если их сценарии полностью покрыты SPA.

**Независимая проверка**: инвентаризировать usages старых actions/views/routes, удалить только
заменённые элементы, затем прогнать их заменяющие SPA/API и тесты маршрутизации.

1. **Дано** `ShowCompetitionsListAction`, `ShowCompetitionAction`,
   `ShowCreateCompetitionFormAction`, `ShowEditCompetitionFormAction` и их Blade views больше
   не нужны, **когда** миграция завершена, **тогда** они удалены вместе с web routes и тестами.
2. **Дано** старый action ещё нужен для неперенесённого сценария, **тогда** он сохраняется и
   явно отмечается как переходный; удаление не ломает ссылки на этапы и протоколы.
3. **Дано** SPA выполняет create/edit/delete, **тогда** используются существующие V1 API
   endpoints, а не legacy POST-формы.

## Граничные случаи

- Прямая загрузка и refresh любого `/app/competitions*` возвращают SPA shell.
- Ссылка может содержать год или другой query-параметр; его нельзя потерять без проверки
  совместимости со SPA-фильтрами.
- Redirect после login/registration и 404 не должен зациклиться.
- Старые ссылки из внешних закладок могут временно получить redirect на соответствующий SPA
  маршрут, если полное удаление legacy URL создаёт неоправданную поломку.
- Ссылки на events, protocol lines, cups и другие ещё не мигрированные функции остаются
  рабочими и не превращаются в несуществующие SPA routes.

## Требования

- **FR-001**: Все внутренние ссылки на competition list MUST использовать `/app/competitions`.
- **FR-002**: Все внутренние ссылки на competition view MUST использовать `/app/competitions/{id}`.
- **FR-003**: Все create/edit ссылки MUST использовать соответствующие SPA routes и SPA auth guard.
- **FR-004**: Root, 404, login, registration, navbar и competition actions MUST быть включены
  в inventory ссылок и обновлены при необходимости.
- **FR-005**: SPA create/edit MUST продолжать использовать существующие V1 API contracts;
  изменение бизнес-правил соревнований не входит в эту фичу.
- **FR-006**: Полностью заменённые Blade views, web actions, routes и их тесты MUST быть удалены
  согласованно; неперенесённые сценарии MUST быть сохранены.
- **FR-007**: Legacy URL, которые нужно временно поддержать для внешних ссылок, MUST делать
  redirect на SPA без рендера старого view и быть явно перечислены в плане.
- **FR-008**: Прямой SPA URL и refresh MUST работать в локальном и production web server setup.
- **FR-009**: Изменение MUST иметь route/link regression tests и frontend router tests; старые
  тесты удаляются только вместе с удалённым поведением.
- **FR-010**: После миграции MUST отсутствовать новые N+1 и дублирующий пользовательский путь
  для соревнований.

## Ключевые сущности

- **Competition SPA route**: публичный или защищённый URL для списка, просмотра, создания и
  редактирования соревнований.
- **Legacy competition entry point**: старый Blade action/view/route, который либо удаляется,
  либо временно перенаправляет на SPA.
- **Competition link**: внутренняя ссылка, redirect или navigation action, ведущая к разделу.

## Критерии успеха

- **SC-001**: 100% инвентаризированных внутренних ссылок на list/view/create/edit ведут на SPA.
- **SC-002**: Сценарии list → view → create/edit проходят без Blade-рендера и полной перезагрузки.
- **SC-003**: Неавторизованный доступ к create/edit всегда приводит к SPA login.
- **SC-004**: Удалённые legacy actions/views/routes не имеют рабочих usages, кроме явно
  документированных redirect-ов.
- **SC-005**: Существующие SPA competition router/API тесты и новые link/route tests проходят.
- **SC-006**: Ссылки на неперенесённые разделы и операции продолжают открывать рабочие страницы.

## Допущения

- V1 API и SPA competition pages из спецификации 005 считаются готовыми и не переписываются.
- Вопрос сохранения внешних legacy URL решается в plan после инвентаризации usages; по умолчанию
  предпочтителен redirect, если это не мешает удалению старого view.
- Полная миграция navbar всего сайта и всех разделов не входит в 011; меняются только competition
  entry points и связанные с ними переходы.
