# Проверка документационного результата

## Предусловия

- Открыта рабочая копия BFO Base с фичей `040-backend-architecture-manifest`.
- Можно читать исходный код и файлы `.specify/memory`, `AGENTS.md`, `CLAUDE.md`.

## Сценарии

1. Откройте `AGENTS.md` и `CLAUDE.md` как агент перед новой бэкенд-фичей. Оба файла должны направить к каноническому манифесту; конституция объявляет его обязательным и сохраняет приоритет своих правил.
2. Проследите путь обновления события по манифесту. Указанные action, command, Application service, aggregate, repository и handler должны существовать и выполнять описанные роли.
3. По матрице агрегатов определите для `Group::updateName`, `Club::disable`, `Competition::updateInfo` и `ProtocolLine::assignPerson` текущий аудит, событие и исключение. Сверьте выводы с исходными файлами.
4. Возьмите задачу из реестра рефакторинга. У неё должны быть путь, риск, ограниченный шаг, зависимость и способ проверки.
5. Проверьте целостность Markdown-ссылок и `git diff --check`. По `git status --short` убедитесь, что исходный код, миграции и тесты не менялись в этой фиче.

## Ожидаемый результат

Каждый сценарий можно завершить чтением документов и кода. Запуск PHPUnit не требуется: эта фича меняет инструкции, а не поведение приложения.
