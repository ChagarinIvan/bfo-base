# Исследование

## Названия после импорта

**Decision**: по уточнению пользователя от 2026-10-18 сохранить существующий маппинг и сравнивать его шаблоны без обычных пробелов. `ElkPathCup` передаёт `groupNamesIgnoringSpaces`; Eloquent adapter применяет `REPLACE(groups.name, ' ', '') LIKE ?` и удаляет пробелы из bound pattern. Пустой список не возвращает дистанций.

**Rationale**: в `Results_night_cup.xlsx` 92 строки, из них 19 мужчин и 6 женщин элиты. `ElkPathXlsxParser` сокращает слова Mужчыны/Жанчыны до М/Ж. `StandardProtocolParser` удаляет пробелы только при построении `normalizedGroupName`; `StandardProtocolLinesFactory` сохраняет исходное отображаемое имя группы. `EloquentDistanceRepository` ищет по `groups.name`, поэтому `%Elite-М` и `%Elite-Ж` не совпадают с пробелами перед и после дефиса.

**Alternatives considered**: менять парсер или глобальную нормализацию нельзя без расширения области и воздействия на другие кубки; широкий шаблон `%Elite%М%` может захватить постороннюю категорию. Точные aliases ночного этапа потребовали бы новых записей для каждого префикса. Игнорирование пробелов сохраняет прежние шаблоны, пол и ID зачётов. Не меняются дефисы, регистр или другие символы сверх прежнего поведения MySQL LIKE.

## Проверка реального файла

**Decision**: сохранить контрольный XLSX в `tests/Fixtures/Protocols/2026/Results_night_cup.xlsx`; integration-тест проходит через `StandardProtocolParser`, `StandardProtocolLinesFactory`, сохранение и реальные критерии `ElkPathCup::calculateEvent()`.

**Rationale**: тест только массива маппинга не обнаружил бы сокращение слов и сохранение пробелов. Для подсчёта каждому результату назначается отдельный активный спортсмен. Проверяются 19/6 результатов, отсутствие смешения, очки победителя и сохранение данных после пересчёта. Старые aliases и посторонняя категория проверяются отдельными короткими fixtures БД.

**Alternatives considered**: чтение корневого файла связывает тест с пользовательским рабочим файлом; отдельный искусственный XLSX не воспроизводит источник дефекта.

## Кэш и уже загруженный этап

**Decision**: использовать существующий `ClearCupCacheService` и действие очистки кубковых таблиц перед формированием актуального результата. Не менять ключи всех кубков и не добавлять миграцию.

**Rationale**: таблицы под тегом cups кэшируются на 1000000 секунд. Изменение сопоставления само по себе старую пустую таблицу не обновляет. Штатная очистка удаляет её без повторного импорта. Эта операция входит в quickstart и интеграционную проверку.

**Alternatives considered**: изменение cache namespace всех кубков создаёт лишний массовый пересчёт; изменение протокола ради сброса кэша затрагивает исходные данные.

## Проверка спецификации

Все FR-001–FR-007 проверяемы. Исправление ограничено поиском групп ElkPathCup без обычных пробелов; обычный groupNames других кубков не меняется. Префикс по-прежнему определяется существующим wildcard, новые категории не добавляются. Неизвестных требований нет. Hooks отсутствуют. Пользователь запросил полный цикл, поэтому согласование отдельных промежуточных шагов не требуется.
