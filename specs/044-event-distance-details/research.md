# Research: параметры дистанции на странице этапа

## Источник значений

**Decision**: Использовать уже загруженный список дистанций события. Для выбранного `distanceId` брать `length` и `points` у соответствующей дистанции.

**Rationale**: `getEventDistances(eventId)` уже вызывается при открытии страницы и после завершения обработки протокола. V1 DTO содержит `id`, `groupName`, `length` и `points`; дополнительное чтение не даст новых данных.

**Alternatives considered**: Отдельный запрос на дистанцию при каждом выборе группы увеличит число запросов и может вернуть устаревшее значение после быстрого переключения. Расчёт длины и КП по строкам протокола дублирует сохранённые параметры.

## Единицы и формат

**Decision**: Считать `length` метрами, делить на 1000 и форматировать как километры для белорусской локали с точностью до трёх десятичных знаков. `points` показывать целым числом с подписью `КП`.

**Rationale**: Дистанции в проекте сохранены в метрах: например, значение `2600` означает `2,6 км`. Три десятичных знака сохраняют точность одного метра. Уже используемые подписи `км` и `КП` находятся в `resources/lang/by.json`.

**Alternatives considered**: Показывать 2600 как километры неверно. Округление до десятых скрывает разницу между близкими дистанциями.

## Место отображения

**Decision**: Показать параметры рядом с выбором дистанции в панели фильтров результатов. Вычисляемое значение обновляется при смене ID без отдельного состояния.

**Rationale**: Посетитель сопоставляет параметры с выбранной группой до чтения результатов. Вычисление от выбранного ID исключает рассинхронизацию при прямой ссылке и обновлении дистанций после обработки протокола.

**Alternatives considered**: Добавить параметры в карточку события означало бы смешать данные всего этапа с данными одной группы. Хранить отдельные копии длины и КП в состоянии страницы означало бы синхронизировать их вручную при каждом переходе.
